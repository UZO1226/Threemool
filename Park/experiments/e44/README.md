# Park/e44: 대표 차단의 결정 감사, 검사한 행동과 실행한 행동 (Kaggle DARROW)

상태: **사전 등록 (2026-11-19).** 가설과 판정 규칙은 검증 결과를 보기 전에 정했다. 새 학습과 고를 설정은 없다. 대표는 바꾸지 않는다.

## 목적

팀 중간점검 (Yoo/analysis/TEAM_RESEARCH_REVIEW_20261117.md) 의 두 지적을 Park 차단에 적용한다.

- 4.3 절 (Lee e74): "검사하는 행동과 실행하는 행동이 다른 설계 문제". 대표 차단도 1 스텝 NH4 여유 검사 뒤에 DO 줄이기, 충돌 조정, 회복 계획이 공기량을 다시 바꾼다. 실행한 공기량이 차단 자신의 검사를 통과하는지, 위반이 어느 단계에서 나오는지 아직 센 적이 없다
- 6.2 절 재현성: "독립 구현의 후보 점수와 행동 선택 검사 추가". 감사 코드 (`Park/code/audit_brake.py`) 는 차단의 trim 경로를 단계별로 다시 계산한다. 결과가 Park/e35 orig 와 같아야 한다

## 방법

- 대표 (FCSRL 4 x 16 앙상블 + 대표 차단), 구성원이 겹치지 않는 묶음 5개. 다시 학습하지 않는다
- `AuditBrake` 로 스텝마다 단계별 공기량 (정책, NH4 하한, 회복 검사, DO 줄이기, 충돌 조정, 회복 계획) 을 기록하고, 마지막으로 공기량을 바꾼 단계를 정한다
- 실행한 최종 공기량에서 차단 자신의 1 스텝 NH4 여유 검사 (다른 구성원 평균 + sigma 에 맞춘 여유 P1 <= 4) 와 DO 한도 검사 (1 스텝 예측 최대 DO <= 1.8) 를 다시 한다
- 실제 위반은 그 행동 다음 스텝의 환경 상태로 센다
- 스텝 기록은 Park/e45 에서도 쓴다

## 평가

검증 40일 x 구성원 5개 = 200 에피소드, 결정적. test 는 쓰지 않는다.

## 가설 (사전 등록)

- H0 (재현, 전제). 묶음 5개 모두 공기량, 비용, 위반률, 개입률이 Park/e35 orig 와 1e-9 안에서 같다. 다르면 나머지를 판정하지 않는다
- H1 (위반의 출처). 실제 NH4 위반 스텝 가운데, 실행한 공기량이 차단 자신의 NH4 검사를 통과하지 못한 스텝 (회복 불가로 본 스텝, 충돌 조정으로 줄인 스텝, 회복 계획이 바꾼 스텝 등) 의 비율이 50% 이상인 묶음이 5개 중 4개 이상이고, 평균도 50% 이상이다. 지지되면 "위반은 대부분 차단이 알고 받아들인 위반" 이고, 기각되면 "위반은 대부분 검사를 통과한 뒤 모델 오차로 생긴다"
- H2 (여유가 맞는가). 자신의 NH4 검사를 통과한 실행 행동의 다음 스텝 NH4 위반률이 1% 이하인 묶음이 4개 이상이고, 평균도 1% 이하다

참고 (판정 없음): 단계별 스텝 비율과 위반률, DO 쪽의 같은 표, 검사를 통과하지 못한 행동의 내역.

## RESULT.md 처리 (미리 정함)

대표 방법은 바꾸지 않는다. 결과는 대표 차단의 기전 설명으로 RESULT.md 해석에 적는다. H0 이 기각되면 원인을 찾을 때까지 다른 결론을 적지 않는다.

## 미리 밝히는 한계

- 감사 코드는 같은 저장소의 차단 함수 (`_base_required_air`, `_recover_air`, `_resolve_conflict`, `_plan_recovery`) 를 다시 부른다. 완전히 따로 쓴 독립 구현은 아니고, trim 단계와 기록만 따로 썼다
- "검사" 는 차단 자신의 대리 모델 예측이다. 환경도 같은 계열 모델이라, 검사를 통과한 행동의 위반은 구성원 사이의 차이에서만 생긴다
- 묶음 5개는 판정 표본이 작다 (4/5 기준). 검증 구간은 e10 부터 반복해서 썼다
