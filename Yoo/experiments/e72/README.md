# e72: 승수 상한 상향과 학습 한도 여유 (마지막 승수 조정)

**2026-11-20 16:28 KST 완료. 사전 기준 미달: dev 한도 충족 FCSRL 6/10, 고정 표현 PPO 7/10 (기준 8/10). 합의대로 이 비용 정의의 승수 조정은 여기서 끝낸다.** [결과 표](results.md), [요약](summary.json), [사전 조건](protocol.json), [학습](train72.py), [실행](run72.py), [집계](report72.py). 학습 코드는 [e70/train70.py](../e70/train70.py) 와 [e68/train68.py](../e68/train68.py) 를 바꾸지 않고 불러 쓰며, 승수 상한과 학습 한도 두 값만 바꾼다. holdout 과 test 는 쓰지 않았다.

## 결과 요약

dev 146일 x 5, 표본 행동 (고정 seed 3개 평균), seed 0 ~ 9, 갱신 500번. 대리 환경 결과이며 현장 성능이 아니다. 학습 20개 모두 정상 종료했고, 갱신 1번 학습 수집 (비용, 보상, 공기) 이 e71 과 20/20 같았다.

| 방법 | 공기량 m³/23.75h | 예산 초과 스텝/일 (한도 0.3) | 한도 충족 seed | 하루 위반율 % | NH4 초과 mg h/L |
| --- | --- | --- | --- | --- | --- |

- **H2 (한도 충족): 미달.** 평균 예산 초과는 두 방법 모두 0.3 아래로 내려갔지만 seed 별 충족은 FCSRL 6/10 (seed 5, 6, 8, 9 초과, 0.32 ~ 0.35), 고정 표현 PPO 7/10 (seed 2, 5, 7 초과) 로 사전 기준 8/10 에 못 미쳤다. FCSRL 의 충족 seed 수는 e70 (6/10) 과 같다.
- **H1 (주, dev): 차이 불명확, 세 조건 1/10.** 지표별로 FCSRL 이 낮은 짝은 공기 8/10, 위반일 8/10, NH4 초과 7/10, 예산 초과 6/10 이다. 평균 차이는 공기 -1,762, NH4 초과 -5.69 로 FCSRL 쪽이지만, 한 짝 안에서 세 지표가 함께 낮은 경우가 거의 없었다. e71 의 7/10 보다 크게 낮아 e71 의 근접 결과는 이 설정에서 재현되지 않았다. val (보조) 은 0/10.
- **H3: ABAC 대비 우위 아님.** 세 지표 모두 나은 seed 는 두 방법 모두 0/10 이다. RL 은 공기를 29 ~ 32 % 적게 쓰지만 위반일과 NH4 초과가 ABAC 보다 많다.
- **e71 대비 교환:** FCSRL 예산 초과는 0.300 에서 0.236, 위반일은 4.52 에서 2.49 % 로 줄었지만 공기는 39,712 에서 42,716 (+7.6 %), NH4 초과는 13.66 에서 21.36 으로 늘었다. 예산 초과 스텝을 줄이는 대신 공기와 NH4 초과 적분을 내준 것이어서 동시 개선이 아니다.

## 결론과 다음

## 왜 하는가

[e71](../e71/README.md) (e70 설정, 갱신 500번) 에서 dev 한도 0.3 충족은 FCSRL 4/10, 고정 표현 PPO 2/10 으로 e70 보다 늘지 않았다. seed 별로 보면 한도를 넘은 FCSRL seed 6개는 모두 마지막 50번 승수 평균이 19.4 ~ 19.8 로 상한 20 근처였고, 갱신 251 ~ 500 의 27 ~ 54 % 동안 상한에 닿아 있었다. 승수가 더 올라갈 수 없어 비용을 더 누르지 못한 것이다. 상한에서 풀려 있던 seed 는 학습 수집 비용이 학습 한도 근처나 그 아래에 있었다.

- **승수 상한 올림:** 상한에 걸린 seed 가 더 누를 수 있게 한다. 값은 아래 시범 학습으로 40 과 100 중에서 정한다.
- **학습 한도 0.2:** 평가 한도 0.3 은 그대로 두고 학습 목표만 낮춘다. 학습 수집 비용이 학습 한도에 모여도 seed 마다 흔들리므로 (e71 FCSRL dev 표준편차 0.08), 같은 값을 목표로 하면 절반 가까이가 넘는다. 0.2 는 평가 한도보다 약 1.1 표준편차 낮아 정규 근사로 10개 중 8개 이상이 0.3 이하일 확률이 약 0.85 다.

## 마지막 조정으로 고정

팀 검토는 같은 자료로 통과할 때까지 설정을 바꾸는 반복을 경계한다. 그래서 사용자와 합의해 e72 를 이 비용 정의의 마지막 승수 조정으로 둔다.

- 상한 선택 규칙과 학습 한도는 본 실험 결과 전에 [protocol.json](protocol.json) 에 고정했다.
- 성공하면 같은 설정으로 새 seed 10 ~ 19 를 확인한 뒤 holdout 을 한 번 쓴다. 실패하면 이 예산에서 한도를 안정적으로 지키지 못한다고 보고하고 더 조정하지 않는다.
- e68 ~ e72 의 모든 시도를 한 표에 공개한다. e72 가 기준을 넘어도 같은 dev 자료에서 세 번째 조정 끝에 넘은 결과이므로 새 seed 확인 전에는 확정으로 쓰지 않는다.

## 바꾸지 않는 것

환경, 비용 (예산 초과 스텝), 보상, 행동, dev 146일 학습, 평가 한도 0.3, 표본 행동 평가, PID 이득 (원본 x 25 / 0.3), 적분 상한 묶음, 갱신 500번, 비교군 (e68 ABAC), 판정 규칙. 두 방법에 똑같이 적용한다.

## 해석상 주의

- 학습 한도를 낮추면 공기가 늘 수 있다. 한도 충족이 늘어도 공기 증가를 함께 보고한다.
- dev 는 학습과 조정, val 은 반복 사용한 개발 자료다. holdout 은 과거 개발 자료여서 독립 미노출 시험이 아니다.
- 모든 결과는 대리 환경 안의 비교이며 현장 절감이 아니다.
