# Park/e21: 같은 학습 예산의 작은 정책 앙상블 (Kaggle DARROW)

상태: **완료 (2026-11-12). H1, H2 모두 지지 안 됨 (2/5).** 업데이트 12번 x 5 앙상블은 공기량 80,209, 비용 4.80 으로 e19 H1 seed 평균 (80,748, 4.98) 보다 둘 다 낮고 비용은 seed 5개 모두보다 낮았지만, 공기량이 seed 2, 3, 4 보다 많아 seed 별로는 2/5 였다. 대표 결과는 e19 H1 으로 둔다. 가설과 판정 규칙은 검증 결과를 보기 전에 정했고 (사전 등록 커밋 `d68ecd0`) 결과를 본 뒤 바꾸지 않았다. 설정은 학습 구간만으로 골랐다.

## 목적

목표는 공기량과 하루 비용을 함께 낮추는 것이다. 비교 기준은 대표 결과인 Park/e19 H1 (검증 seed 평균 공기량 80,748, 비용 4.98) 이다.

## e20 에서 남은 문제

- e20 에서 seed 5개 정책의 행동 평균은 e19 H1 seed 5개 모두보다 공기량과 비용이 낮았다. 하지만 학습을 5번 해서 학습 예산이 PROTOCOL v1 의 5배였다.
- 같은 예산으로 비슷한 효과를 내야 대표 결과로 쓸 수 있다.

## 버린 후보 (학습 구간)

- 정책 하나의 행동을 시간 방향으로 평활 (지수 이동 평균 0.3, 0.5, 0.7, 3스텝 중앙값): e19 H1 보다 둘 다 낮은 seed 가 0 ~ 2 였다.
- 스냅샷 앙상블 (학습 한 번의 마지막 3 ~ 8개 정책 평균): 둘 다 낮은 seed 가 모두 1/5 였다. 학습 한 번 안의 정책들은 서로 너무 비슷하다.
- 두 결과를 보면 앙상블 효과는 서로 다른 seed 의 정책을 합칠 때 생긴다.

## 방법

seed 0 ~ 4 정책을 각각 업데이트 12번만 학습해 (`train_darrow.py --updates 12`, e12 A 와 같은 학습 중 차단 target 3.5) 행동을 평균한다. 5개 합계는 업데이트 60번, 364,800 전이로 PROTOCOL v1 의 학습 예산 401,280 전이 안이다. 평가에는 e19 H1 차단을 그대로 건다.

학습에는 업데이트 수에 묶인 스케줄이 없어서, 업데이트 12번 학습은 e12 A 학습의 앞 12번과 같다. 이것은 e12 A 를 `--save-every 2` 로 다시 학습한 12번째 정책과 `--updates 12` 정책의 가중치가 같은지로 확인한다 (결과에 적음). 다시 학습한 마지막 정책은 기존 e12 A 와 5개 모두 같았다.

## 설정 고르기 (학습 구간만)

학습 구간 40일(4일 간격) x 구성원 5개, seed 5개의 업데이트 6, 8, 10, 12번 정책 평균. 업데이트 13번 이하만 예산 안이다. 규칙은 결과를 보기 전에 정했다: "평균 비용과 평균 공기량이 e19 H1 seed 평균보다 낮은 것 중, 둘 다 이긴 seed 가 가장 많은 것 (3 이상, 같으면 공기량이 적은 것). 없으면 버린다".

| 방법 | 공기량 | 하루 비용 | 개입 % | e19 H1 보다 둘 다 낮은 seed |
| --- | --- | --- | --- | --- |
| e19 H1 seed 평균 | 68,224 | 2.375 | | |
| **업데이트 12번 x 5 (규칙으로 고름)** | **66,636** | **2.030** | 10.7 | 4/5 |
| 업데이트 10번 x 5 | 68,611 | 2.080 | 8.2 | 3/5 |

## 조건과 평가

검증 40일 x 구성원 5개 = 200 에피소드를 결정적으로 돈다. 앙상블은 제어기 하나라 값이 하나다. test 는 쓰지 않는다.

## 가설 (사전 등록)

앙상블 값과 e19 H1 의 seed 5개를 비교한다. 앙상블이 seed 5개 중 3개 이상보다 공기량과 하루 비용이 둘 다 낮고, seed 평균보다도 둘 다 낮으면 지지로 적는다.

- H1 (주 가설). 업데이트 12번 x 5
- H2. 업데이트 10번 x 5

## RESULT.md 처리 (미리 정함)

H1 이 지지되면 학습 예산이 PROTOCOL v1 안이므로 대표 결과를 e21 H1 으로 바꾼다. seed 평균 ± 표준편차 대신 값 하나라는 점을 함께 적는다. H2 만 지지되면 대표 결과는 바꾸지 않는다.

## 미리 밝히는 한계

- 앙상블은 제어기 하나라 seed 사이 편차를 낼 수 없다. 다른 seed 묶음 (예: seed 5 ~ 9) 에서도 같은 효과일지는 이번에 보지 않는다
- 실행 시 정책 계산이 5배다 (작은 신경망이라 실제 부담은 작다)
- 학습 구간에서 고른 업데이트 수가 검증 구간(겨울) 에서도 가장 좋을지는 모른다
- e10 ~ e20 과 같은 대리 모델 한계

## 실행 명령

```bash
export OMP_NUM_THREADS=1
cd Park/code
for s in 0 1 2 3 4; do python train_darrow.py --method fcsrl --seed $s --data <Park/data/darrow>/darrow_15min.pkl --surrogate <Park/data/darrow>/darrow_surrogate_gbm.pkl --out <결과>/dw_u12_runs/A_s$s --min-brake-target 3.5 --updates 12 --save-every 2; done
cd ../experiments/e21
python run_e21.py run --data <Park/data/darrow>/darrow_15min.pkl --surrogate <Park/data/darrow>/darrow_surrogate_gbm.pkl --runs <결과>/dw_u12_runs --out <결과>/e21
python run_e21.py report --out <결과>/e21 --e19 <결과>/e19 --md results.md
```

## 해석

- 작은 앙상블도 비용은 크게 낮췄다 (H1 4.80, H2 4.73, e19 H1 seed 중 가장 낮은 4.82 보다도 낮음). DO 위반이 1.75% 에서 1.56% 로 줄고 차단 개입이 33% 에서 15 ~ 17% 로 줄었다.
- 공기량은 학습을 덜 할수록 많다 (업데이트 10번 81,798, 12번 80,209, 66번 78,933). 정책이 공기를 아끼는 법은 학습 뒷부분에서 배운다.
- 그래서 예산 안의 앙상블은 비용과 공기량을 맞바꾼다. 학습 구간에서는 업데이트 12번이 공기량도 낮았지만 검증 구간(겨울) 에서는 아니었다.
- 같은 예산에서 공기량과 비용을 함께 낮추려면 앙상블 구성원을 더 길게 학습해야 하고, 그러면 구성원 수가 줄어든다 (예: 업데이트 33번 x 2). 이것은 다음 실험 후보다.
