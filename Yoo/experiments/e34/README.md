# e34: 행동, 목적함수와 평가 지표 감사

후속 확인(e35): Kaggle 공식 설명에서 공기 단위m³/h와 센서 위치를 확인했다. 아래 감사 당시 미확인이던 단위의 근거가 확보됐다. 또한 DO1/2/3과 공기3/4/5의 대응에 비춰 기존 대리 모델의 단조 제약 대상이 잘못됐음을 발견했다. 아래 산술 검산 통과는 환경의 물리적 타당성을 증명하지 않는다. [e35 정정과 대조](../e35/README.md).

2026-11-10 완료. 신규 학습 없이 e33의 6개 최종 정책을 다시 평가하고 저장된 지표를 검산했다. 기존 e30/e33의 환경, 정책, 학습 결과는 바꾸지 않았다. 실행 결과는 [results.md](results.md), 전체 수치와 SHA256은 [audit.json](audit.json)이다.

## 무엇을 학습하는가

주 목적은 **정해진 NH4/DO 제약을 만족하면서 총 공기 사용량을 최소화**하는 것이다. 수질과 공기량을 모두 무조건 최소화하는 문제가 아니다. 실제 에너지 소비량(kWh)은 현재 계산하지 않는다.

정책은 15분마다 정규화된 행동 하나를 출력한다. 모방 학습한 초기 정책의 출력에 RL Actor의 보정량을 더한다. 학습 중에는 Gaussian에서 행동을 샘플링하고, 평가 때는 평균을 사용한다. 실행 행동을 [-1, 1]로 자른 뒤 다음과 같이 변환한다.

```
a_exec = clip(a, -1, 1)
Q_air = (a_exec + 1) * 4500
```

행동 -1, 0, 1은 각각 총 유량 0, 4500, 9000에 해당한다. 5개 구간의 배분은 해당 시각 기록의 비율로 정해지고 정책이 직접 선택하지 않는다. NH4, NO3, DO의 다음 상태는 별도 대리 모델이 예측한다. FCSRL의 표현망은 정책을 돕는 보조 표현을 학습하며 실제 액추에이터 출력은 Actor의 공기량 행동이다.

코드는 유량을 Nm³/h로 표기해 왔지만 원본 online CSV 헤더에는 단위나 표준상태 조건이 없다. 이 감사에서는 기존 m³/h 변환 가정을 명시하고 N 표기를 확정하지 않는다. 절대 부피의 단위 확인은 남아 있으며 동일 변환하의 상대 절감률은 별도로 계산할 수 있다.

## 수식과 지표

하루 파일은 15분 간격 96개 관측값이다. 첫 관측에서 시작해 다음 95개 관측 시점까지 전이하므로 평가 길이는 **23.75시간**이다. 마지막 시점에서 다음 날로 넘어가는 1개 전이는 평가하지 않는다. 무조건 24시간 부피로 표기하거나 24/23.75를 곱해 실제 일일 소비량처럼 해석하면 안 된다.

| 지표 | 실제 계산 | 뜻과 단위 |
| --- | --- | --- |
| 공기 사용량 V | sum(Q_air[t] * 0.25), t=0..94 | 23.75시간의 부피, m³/h 가정하에 m³ |
| 보상 r | -Q_air[t] / 9000 | 공기량 감소를 유도하는 무차원 학습 신호 |
| 할인 없는 누적 보상 R | -V / 2250 | 고정 간격에서는 부피와 정확히 비례 |
| NH4 비용 C_N | sum(I(NH4[t+1] > 4)) | 기준 초과 표본 수. mg N/L가 아님 |
| DO 비용 C_D | sum(I(max(DO1,DO2,DO3)[t+1] > 2)) | 3개 센서 중 하나라도 초과한 표본 수 |
| 위반률 | 100 * C / 95 | 해당 변수의 초과 표본 비율(%) |
| 평균 제약 만족 | E[C_N] <= 6 and E[C_D] <= 6 | 두 조건 모두 만족해야 함 |
| 에피소드 충족률 | mean(C_N <= 6 and C_D <= 6) * 100 | 날짜와 모델 구성원 조합 중 충족한 비율 |
| seed 충족 수 | 각 정책 seed의 두 평균 조건 만족 개수 | 학습 초기화에 대한 재현성 |
| NH4 초과 적분(이번 추가) | sum(max(NH4[t+1]-4,0) * 0.25) | 초과 강도와 지속시간, mg N h/L 가정. 질량 아님 |
| NH4 평균, p95, 최대 | 전이 후 농도 표본 요약 | 위반 횟수만으로 빠진 초과 강도를 보완 |
| 실제 에너지 | 미계산 | 전력 계측이나 검증한 송풍기 모델 필요 |

한도6은 NH4 농도6이나 독립적인 위험 사건6건이 아니다. 95개 중 평균6개(6.316%)를 허용한다는 뜻이다. 각 표본을 15분 구간 대표값으로 보면 약90분에 해당하지만 연속 관측으로 확정한 실제 초과시간은 아니다. NH4 4.01과9는 기존 비용에서는 똑같이1이다. 두 센서군이 같은 시점에 초과하면 기존 합산 비용은2가 된다.

NH4 농도4, DO 농도2와 평균 허용 횟수6은 연구 설정이다. Tilburg 현장의 법적 방류 기준으로 확인된 값이 아니다. 온라인 NH4 센서값을 최종 방류수 농도로 단정하지 않는다. lab effluent 자료는 현재 RL 학습에 쓰지 않았다.

## 검산 결과

- [-2,-1,0,1,2] 입력의 실행 유량은 [0,0,4500,9000,9000]으로 확인했다.
- 행동0을 95회 적용하는 산술값은 공기 부피106875, 누적 보상-47.5다.
- 검증40일 모두 관측96개와 15분 간격을 확인했다.
- 실제 재평가의 모든 전이에서 구간 유량 합, 실행 행동 변환, NH4/DO 비용 분해, 부피와 누적 보상의 관계를 검산했다.
- e33의 6개 체크포인트 각각에서 공기량, 두 비용, 에피소드 충족률, 두 평균 한도 판정이 저장값과 일치했다. 원래 에피소드 JSON의 평균도 독립 집계했다.
- e30의 위반률을 비용으로 돌리는 `위반률 * 0.95`는 95/100이므로 맞다. 보상에 0.25가 없다는 사실도 고정 시간 간격에서는 상수 척도 차이이지 적분 누락 오류가 아니다.

**검사한 범위에서 합계, 분모, 시간 환산의 산술 오류는 발견하지 않았다.** 다만 아래 문제는 계산식이 실행된다는 것과 별개다.

## 목표 설계와 해석의 문제

### 1. 에너지와 공기량을 혼용했다

송풍기 전력은 유량 외에도 압력 상승과 송풍기/모터 효율에 의존한다. 공기량 10% 감소를 곧바로 전력 10% 감소라고 주장할 수 없다. 현재 본 데이터 실험은 공기 사용량 절감이며 실제 에너지 절감은 미측정이다. [미국 DOE, Lower Aeration Tank Pressure](https://betterbuildingssolutioncenter.energy.gov/sites/default/files/attachments/Tipsheet%202%20-%20Lower%20Aeration%20Tanks%20-%20Final.pdf).

### 2. DO 상한의 공정 근거가 부족하다

현재는 `max(DO)>2`를 불이익으로 처리한다. 이는 과도한 산소 공급 억제라는 실험상 의미는 있으나 모든 구간의 수질 안전 정의로 검증되지 않았다. EPA 매뉴얼은 일반적인 질산화조 유입부에서 DO 2 이상을 설명하는 동시에 긴 체류시간이나 동시 질산화/탈질 조건에서는 더 낮은 농도도 설명한다. 따라서 센서 위치와 구간 역할을 모른 채 `DO>2` 또는 반대로 `DO<2`를 일괄 안전 기준으로 삼을 수 없다. [EPA Nutrient Control Design Manual, Table 10-5, PDF 286쪽](https://www.epa.gov/sites/default/files/2019-02/documents/nutrient-control-design-manual.pdf).

현재 보상은 공기를 줄이도록 하고 DO 상한도 산소 증가를 억제하므로 NH4 처리 요구와 충돌할 수 있다. 이것이 e33 실패의 단독 원인이라는 증거는 없다. 실제로 e33 검증 평균 DO 비용은 모든 seed에서6 이하다. 한편 e31에서는 NH4 악화를 DO 개선이 합산 비용에서 가렸고, e33 분리 제약은 그 상쇄만 막았다. 분리만으로 DO 기준 자체가 타당해지는 것은 아니다.

### 3. 학습의 시간 목표와 결과표가 다르다

학습 가치와 GAE는 gamma=0.99인 할인 반환을 사용한다. 마지막 전이까지의 할인 인자는0.99^94=약0.389다. 보고 지표와 PID 갱신은 할인하지 않은95개 전이 합계다. 마지막 시점에서는 GAE 연결을 끊되 다음 상태의 가치를 bootstrap한다.

이는 계속 운전하는 공정의 시간 제한을 근사하는 일반적인 선택일 수 있으므로 무조건 구현 버그라고 할 수 없다. 그러나 하루 단위의 유한 구간 부피/횟수 최적화와 정확히 같은 목적도 아니다. 유한 하루 문제라면 할인 없는 목표와 종료 가치0을 함께 대조하고, 연속 운전 문제라면 실제 연속 상태 전이와 평가 구간을 맞춰야 한다. gamma만 높여 해결됐다고 간주하지 않는다. 특히 하루 reset은 실제 다음 날 피해를 평가에서 제외하므로 구간 연결 영향도 별도 검증이 필요하다.

### 4. 제어 정보와 환경 신뢰도 한계가 남았다

환경 전이는 유입 성분4개와 현재5구간 배분, 직전5구간 유량을 추가로 사용하지만 정책 관측에는 이 정보가 온전히 들어가지 않는다. 현재 정책은 총 공기량만 조절하고 배분은 기록 비율에 의존한다. 따라서 처리 부하와 산소 공급 위치에 맞춰 공기를 아끼는 제어를 학습하기 어려울 가능성이 있다. 인과적 주원인은 아직 확정하지 않았다.

e30 기록 운전 재생에서 DO 초과 탐지율은1.36%에 불과하다. 이번에도 똑같은 기록 행동의 NH4 비용은 실측16.45, 모델25.59로 다르다. 모델 내 제약 만족을 실제 공정 수질 만족으로 번역할 수 없다. 절대 부피, 온라인 센서 위치, 최소 송풍량과 행동 변화율의 운전 가능 조건도 추가 근거가 필요하다.

## 공기량은 무엇과 비교했는가

동일 검증40일에서 초기 모방 정책은103011.19, 실제 기록 공기는84859.76이다. 아래는 e33의 seed2개 평균이며 모두23.75시간 부피다.

| 정책 | 공기량 | 초기 모방 정책 대비 | 기록 운전 대비 | NH4 비용 | DO 비용 | 두 평균 한도 충족 seed |
| --- | --- | --- | --- | --- | --- | --- |
| PPO | 85517.30 | -16.98% | +0.77% | 7.133 | 1.913 | 1/2 |
| FCSRL | 90735.21 | -11.92% | +6.92% | 15.830 | 2.058 | 1/2 |
| FCSRL Actor 보정 | 84470.02 | -18.00% | -0.46% | 6.945 | 1.675 | 0/2 |

학습으로 초기 정책의 과도한 공기 사용을 줄인 부분은 있다. 그러나 기록 운전 대비 큰 절감과 두 제약의 재현성 있는 동시 만족은 입증하지 못했다. 초기 정책은 학습 날짜에서는 두 평균 한도를 만족했지만 검증 날짜에서는 NH4 7.73으로 미충족이다. 초기 정책도 검증 일반화의 예외가 아니다.

기록 운전과 정책의 공기량은 같은 시간 구간에서 비교할 수 있지만 수질은 실측과 모델 예측을 구분해야 한다. 모델끼리 비교하려면 기록 행동 재생의 모델 결과를 기준으로 쓰고 그 재생 오차도 함께 공개한다. 추가된 NH4 초과 적분은 탐색 진단이며 이를 보고 유리한 평가 지표로 교체하지 않는다.

## 다음 작업의 우선순위

1. **공정 정의 점검:** DARROW 원자료의 센서 위치, 공기 단위와 DO 운전 범위의 근거를 먼저 찾는다. 기존 `DO>2`는 역사적 연구 제약으로 남기고 새 설정과 혼합하지 않는다. 목표를 맞추기 위해 한도를 사후 완화하지 않는다.
2. **같은 품질에서 공기를 줄이는 비교:** 초기 모방 정책, 기록 행동 재생, PPO, FCSRL, Actor 보정을 같은 환경과 날짜에서 비교한다. 공기량만 감소하고 NH4가 악화하면 성공으로 판정하지 않는다. 평균 외에 초과 강도, 나쁜 날짜와 seed 편차를 같이 기록한다.
3. **첫 알고리즘 대조 후보는 관측 누락 보완:** 먼저 현재 구간 배분과 직전 구간별 유량을 정책에도 제공하는 조건을 비교한다. 의사결정 당시 외부 배분 제어기로부터 알 수 있다는 가정을 명시하며 미래 수질이나 미래 운전은 넣지 않는다. 원 FCSRL의 dynamics/feasibility 표현과 총량 행동을 유지한다. 보조 유입 성분과 과거 이력 추가는 별도 대조로 분리한다.
4. **시간 목표 정렬은 별도 대조:** 관측 수정과 섞지 않고 유한 구간 목적 또는 연속 운전 목적을 명시해 discount/종료 처리를 검증한다. 과거의 5분 계수를 15분에 그대로 둔 영향도 구분한다.
5. **환경 검증과 채택:** 기록 운전의 전이/장기 재생, NH4와 DO의 탐지율/FPR, 행동 외삽을 확인한다. 모델 오차가 큰 구간에서 얻은 절감은 현장 성과로 주장하지 않는다. 반복 사용한 검증 날짜는 개발용이며 최종 테스트로 부르지 않는다.

새 장치를 무작정 붙이거나 공기 벌점만 크게 하는 것보다, 목적 정의와 입력 누락을 먼저 점검한다. 공기량 절감 크기는 미리 보장할 수 없다. 위 후속 대조의 학습은 이번 감사에서 시작하지 않았다.

## 재현과 실행 환경

원본 데이터는 [Kaggle DARROW](https://www.kaggle.com/competitions/dynamic-modeling-of-wastewater-treatment-process/data)다. 준비 파일과 분할은 e30 그대로다. 검증40일만 평가하고 test41일은 평가하지 않았다. 체크포인트는 e33 각401280전이 학습의 최종 모델이다.

실행 기반 커밋은016790a, 새 감사 코드의 정확한 SHA256은 audit.json의 `audit_script_sha256`이다. 다른 팀 코드를 새로 복사하지 않고 e30/e33의 기존 의존성을 사용했다. 서버의 기존 Python3.10.19 환경, torch2.14.1+cu130, numpy1.23.5, sklearn1.7.2, CPU 1스레드를 사용했다. 전체 출력은 `/home/jio/fcsrl_src/results/e34/`에 있다.

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 OMP_WAIT_POLICY=PASSIVE \
/home/jio/fcsrl_src/.venv/bin/python Yoo/experiments/e34/audit.py \
  --prepared /home/jio/fcsrl_src/results/e30/prepared \
  --runs /home/jio/fcsrl_src/results/e33/main \
  --out /home/jio/fcsrl_src/results/e34
```

평가와 검산은 통과했다. 학습 및 실제 운전은 수행하지 않았다.
