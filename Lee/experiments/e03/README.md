# Lee/e03: 제약이 엄격할수록 FCSRL 의 이점이 커지는가

## 목적

FCSRL 논문의 주장 하나를 우리 환경에서 직접 검증한다. 논문은 비용 한도 ε 를 5, 10,
20, 30, 40 으로 바꿔 보고 "한도가 엄격할수록 FCSRL 과 다른 방법의 차이가 커지며,
30 이상으로 느슨하면 SALE, VC 와 비슷해진다"고 보고했다 (논문 5절, 우리 분석 노트의
실험 요약).

Lee/e02 에서 비용을 이진값으로 바꿨으므로 이제 논문의 전제(명제 4.1 의 이진 비용)가
성립한다. 그 상태에서 한도만 바꿔 가며 FCSRL 과 PPO-Lag 의 차이가 한도에 따라 어떻게
변하는지 본다. e02 는 한도 72 한 점만 봤고 그 점에서는 FCSRL 이 PPO 보다 나을 근거가
없었는데, 논문 주장대로라면 더 엄격한 한도에서 FCSRL 쪽이 유리해져야 한다.

## 바꾼 것

| 항목 | Lee/e02 | Lee/e03 |
| --- | --- | --- |
| 비용 모드 | mean, binary | binary 만 |
| 하루 한도 | 72 | 50 (엄격), 110 (느슨) |

한도 72 지점은 Lee/e02 의 이진 비용 결과를 그대로 가운데 점으로 쓴다. e02 와 설정,
코드, seed, 학습량, 준비 산출물이 같으므로 같은 조건의 세 점이 된다.

나머지는 모두 e02 와 같다. 방법 2개(PPO-Lag, FCSRL + PPO), seed 3개(0, 1, 2),
40 갱신, 각 230,400 전이, 같은 초기 상태와 관측 정규화 통계, 같은 신경망과 평가 방법
이다. PID 계수는 e01 부터 쓴 같은 규칙(기본값 x 15/한도)으로 한도에 맞춰 환산한다.

새 실행 수는 2 한도 x 2 방법 x 3 seed = 12 개다.

## 한도 50 과 110 의 근거

학습 전에 측정한 기준 제어 결과다 (건기, 평가 구간 7~14일, Lee/e01 README 와 같은 값).

| 기준 제어 | 폭기 kWh/day | 하루 위반 스텝 |
| --- | --- | --- |
| 최대 폭기 KLa5=240 | 4,265.6 | 45.6 (물리적 하한) |
| DO PI | 3,717.8 | 49.3 |
| 기본 폭기 KLa5=84 | 3,341.4 | 182.1 |

- 50 은 물리적 하한 45.6 바로 위다. 거의 최대 폭기로만 만족할 수 있는 엄격한 한도이며,
  논문이 말하는 "제약이 빡빡한" 영역에 해당한다. DO PI 의 49.3 과도 비슷하다.
- 110 은 기본 폭기 182.1 과 하한 사이의 느슨한 쪽이다. e02 에서 이진 비용 PPO 가 87.8,
  FCSRL 이 119.0 스텝이었으므로, 두 방법이 큰 무리 없이 도달하는 범위다. 논문이 말하는
  "한도가 느슨하면 차이가 없어지는" 영역에 해당한다.
- 세 점 50, 72, 110 은 학습 결과가 아니라 기준 제어 측정값과 e02 도달 범위로 정했고,
  실행 뒤에 바꾸지 않는다.

## 가설 (사전 등록)

- H5. 한도가 엄격할수록 FCSRL + PPO 와 PPO-Lag 의 차이(순간 위반 기준)가 FCSRL 에
  유리한 쪽으로 커진다. 즉 `FCSRL - PPO` 값이 한도 50, 72, 110 순으로 증가한다
  (50 에서 가장 작거나 음수).
- H6. 느슨한 한도 110 에서는 두 방법의 차이가 작다.
- H7. 한도가 엄격할수록 두 방법 모두 폭기 에너지를 더 쓴다.

e02 에서 한도 72 의 `FCSRL - PPO` 는 순간 위반 +10.81%p 였다. H5 가 맞으면 한도 50 에서
이 값이 뚜렷하게 작아져야 한다. 반대로 50 에서도 비슷하거나 더 커지면, 적어도 이
환경에서는 논문의 "엄격할수록 유리" 주장이 재현되지 않는다는 뜻이다. 어느 쪽이든
그대로 기록한다.

## 실행

```bash
export BSM1_ARCHIVE=.../BSM1.zip
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
python -u Lee/experiments/e01/run_all.py --prepared <결과>/e01_prepared --out <결과>/e03_runs_l50 \
  --updates 40 --parallel 6 --modes binary --cost-limit 50 --upstream <원본 FCSRL 경로>
python -u Lee/experiments/e01/run_all.py --prepared <결과>/e01_prepared --out <결과>/e03_runs_l110 \
  --updates 40 --parallel 6 --modes binary --cost-limit 110 --upstream <원본 FCSRL 경로>
```

e01 과 e02 에서 쓴 스크립트에 한도 인자(`--cost-limit`)와 모드 선택(`--modes`)을
추가했다. 인자를 주지 않으면 기본값이 모드의 기존 한도(mean 288, binary 72)라서 e01 과
e02 의 설정은 그대로다. 기본값이 같음을 확인했고, e01 과 e02 실행 당시의 스크립트는
각 실험의 summary.json 에 적힌 커밋에 있다.

준비 산출물과 학습 전 검사는 e01 의 것을 그대로 쓴다. run_all.py 가 실행할 때마다
준비 산출물 sha256 과 원본 FCSRL 커밋 무결성을 다시 검사한다.

예상 실행 시간은 한 묶음당 약 1시간, 두 묶음 합쳐 약 2시간이다.

## 미리 밝히는 한계

- 한도 50 은 물리적 하한 바로 위라 만족하지 못할 수 있다. 만족 여부와 함께 도달한
  값을 보고한다.
- 40 갱신은 수렴이 아니다. e02 에서 하루 비용이 계속 내려가는 중이었다. 한도별 비교는
  같은 예산에서의 비교이지 수렴 지점의 비교가 아니다.
- seed 3개의 탐색적 비교이며 Welch 검정에 다중 비교 보정을 하지 않는다.
- 한도 72 점은 새로 돌리지 않고 e02 결과를 재사용한다. 같은 코드와 설정이지만 e02
  실행과 e03 실행의 시점이 다르다.
- 논문은 Safety Gymnasium 로봇 과제에서 ε 를 바꿨고 우리는 폐수처리 환경에서 다른
  척도의 한도를 바꾼다. 재현이 아니라 같은 취지의 점검이다.
