# Park/e46: NH4 분석계 지연에 대한 견고성 (Kaggle DARROW)

상태: **사전 등록 (2026-11-19).** 가설과 판정 규칙은 검증 결과를 보기 전에 정했다. 새 학습과 고를 설정은 없다 (ABAC 는 Park/e43 이 고른 값). 대표는 바꾸지 않는다.

## 목적

팀 중간점검 (Yoo/analysis/TEAM_RESEARCH_REVIEW_20261117.md) 8절 6번은 "동일 계산 환경 밖의 견고성" 으로 모델 교체와 **센서/입력 지연** 을 들었고, 5.1 절의 ABAC 문헌 (Water Environment Research 2026) 은 센서와 내부 제어 루프의 지연을 고려했다. 모델 교체는 Park/e38 ~ e42 에서 보았다. 이 실험은 현장 NH4 분석계의 측정 지연 (보통 수 분 ~ 수십 분) 을 넣는다.

정책과 차단은 지금 NH4 를 보고 공기량을 정한다. 지연이 있으면 둘 다 오래된 NH4 로 판단한다. 차단의 1 스텝 예측이 오래된 상태에서 출발하므로 여유 (P1) 가 지연을 흡수하는지, 그리고 Park/e38, e39 처럼 FCSRL 이 PPO-Lag 보다 덜 무너지는지 본다.

## 방법

- 지연 d: 정책과 차단 (ABAC 는 제어기) 이 보는 관측 NH4 를 d 스텝 전 값으로 바꾼다 (`Park/code/audit_brake.py` 의 `rollout_log(delay=d)`). 첫 d 스텝은 그날 첫 관측을 쓴다. 다른 관측, 환경의 실제 상태와 비용은 그대로다
- 주 판정 d = 1 (15분). 참고 d = 2 (30분)
- 방법: FCSRL 대표 (묶음 5개, d = 0, 1, 2), 같은 설정의 PPO-Lag + 대표 차단 (Park/e37, 묶음 5개, d = 0, 1), ABAC (Park/e43 이 고른 값, d = 0, 1, 2), 참고로 기본 PPO-Lag 차단 없음 (seed 5개, d = 1)
- d = 0 값은 Park/e35 orig (FCSRL), Park/e37 (PPO-Lag), Park/e43 검증 (ABAC) 을 그대로 쓴다. 지연 0 의 `rollout_log` 는 `evaluate` 와 같은 값을 낸다 (Park/e44 재현 확인)
- 다시 학습하지 않는다. 여유도 다시 맞추지 않는다

## 평가

검증 40일 x 구성원 5개 = 200 에피소드, 결정적. test 는 쓰지 않는다.

## 가설 (사전 등록)

- H1 (지연에서도 이득이 남는가). 지연 15분의 FCSRL 대표가 RESULT.md 공식 표의 기본 PPO-Lag (차단 없음, 지연 없음, 90,121 Nm3/일, 하루 비용 10.79) 보다 공기량과 비용이 둘 다 낮은 묶음이 5개 중 4개 이상이고, 평균도 둘 다 낮다
- H2 (FCSRL 이 덜 무너지는가). 지연 0 에서 15분으로 갈 때 하루 비용 증가가 FCSRL 대표 쪽이 같은 묶음의 PPO-Lag 보다 작은 묶음이 4개 이상이고, 평균 증가도 작다

참고 (판정 없음): 지연 30분, ABAC 의 지연 영향, 지연을 준 기본 PPO-Lag.

## RESULT.md 처리 (미리 정함)

대표 방법은 바꾸지 않는다.

- H1 지지: "NH4 분석계가 15분 늦어도 대표는 공식 기준선보다 공기량과 비용이 둘 다 낮다" 고 적는다
- H1 기각: 한계에 "대표의 이득은 지연 없는 NH4 측정에 기댄다" 고 적는다
- H2 는 Park/e38, e39 의 H2 와 같은 방식으로 적는다

## 미리 밝히는 한계

- 지연은 NH4 하나에만, 고정 스텝 단위로 넣었다. 실제 분석계는 지연 외에 잡음, 표본 주기, 고장도 있다
- 정책과 차단 모두 지연 없는 자료로 만들었다. 지연을 알고 보정하는 방법 (예측으로 지연 메우기) 은 보지 않는다
- H1 의 기준선은 지연이 없는 값이다 (대표에 불리한 비교). 지연을 준 기본 PPO-Lag 는 참고로 적는다
- 묶음 5개는 판정 표본이 작다 (4/5 기준). 검증 구간은 e10 부터 반복해서 썼다
