# Park/e56: 검증 구간 공기량 곡선으로 본 예측 제어와의 같은 공기량 비교 (Kaggle DARROW)

상태: **사전 등록 (2026-11-21).** 손잡이 값, 곡선 규칙, 가설은 검증 구간을 돌리기 전에 정했다. 대표는 바꾸지 않는다.

## 목적

"같은 정보와 같은 공기량에서 학습 정책이 짧은 예측 구간 모델 예측 제어 위에 더하는 몫이 있는가" 는 Park/e48 (지표 목적, -21.8%) 과 Park/e52 (초과량 목적, -3.1%) 에서 두 번 모두 맞춤 실패로 판정하지 못했다 (Park/e55 주장 지도의 한계). 실패 원인은 학습 구간에서 맞춘 손잡이의 공기량이 검증 구간에서 달라지는 것이다. 이 실험은 맞추기 자체를 없앤다. 예측 제어를 여러 공기 가중치로 검증 구간에서 돌려 공기량, 비용 곡선을 만들고, 대표 묶음마다 같은 공기량의 곡선 비용과 비교한다. 이 문제를 푸는 세 가지 길 (e56 곡선, e57 공기 예산, e58 같은 차단 위의 예측 제어) 가운데 하나다.

## 방법

- 예측 제어: `Park/code/mpc_darrow.py` 의 `ShortMPC`, `objective='excess'`, NH4 여유 1.2 (Park/e52 가 고른 값), 1시간 예측 구간, 후보는 e48, e52 와 같다
- 공기 가중치: 2.5, 1.5, 0.7, 0.5, 0.35, 0.25 를 새로 돌리고, 1.0 은 Park/e52 의 검증 값 (같은 코드, 결정적) 을 그대로 쓴다
- 곡선: 7개 점 가운데 공기량이 같거나 적으면서 비용이 더 낮은 점이 있는 점 (지배되는 점) 을 빼고, 남은 점을 공기량 순으로 선형 보간한다. 대표 묶음의 공기량이 곡선 범위 밖이면 그 묶음은 "대표가 낮지 않음" 으로 센다
- 손잡이 범위는 학습 구간 4일 (마지막 40일에서 10일 간격) 사전 점검으로 정했다 (공기 가중치 0.5, 0.7, 1.0 에서 공기량 84,606, 81,494, 79,706). 검증 구간은 Park/e52 의 한 점 말고는 보지 않았다
- 대표는 Park/e35 orig 의 묶음 5개 값을 쓴다

## 이 비교가 누구에게 유리한가

예측 제어는 검증 구간 자체에서 손잡이를 바꿔 가며 곡선을 만들고, 지배되지 않는 점만 남긴다. 대표는 다시 고르지 않는다. 따라서 이 비교는 예측 제어에 유리하다. 이 조건에서도 대표가 낮으면 "학습 정책이 예측 제어 위에 더하는 몫이 있다" 는 주장이 강해진다.

## 평가

검증 40일 x 구성원 5개 = 200 에피소드, 결정적. test 는 쓰지 않는다.

## 가설 (사전 등록)

- H1. 대표 묶음 5개 모두 공기량이 곡선 범위 안이고, 대표의 하루 비용이 같은 공기량의 예측 제어 곡선 비용보다 낮은 묶음이 5개 중 4개 이상이며 평균도 낮다

참고 (판정 없음): 차단만, ABAC (Park/e43) 의 공기량에서의 곡선 비용, 묶음 차이의 신뢰구간.

## RESULT.md 처리 (미리 정함)

대표 방법은 바꾸지 않는다.

- H1 지지: "검증 구간에서 손잡이를 바꿔 만든 예측 제어 곡선과 비교해도 같은 공기량에서 대표의 하루 비용이 낮다" 고 적는다
- H1 기각: "같은 공기량에서 1시간 예측 제어가 학습 정책 없이 대표만큼 한다" 고 한계에 적는다. 예측 제어가 4/5 이상 낮으면 대표를 바꿀지는 팀과 정한다

## 미리 밝히는 한계

- 곡선은 7개 점의 선형 보간이다. 점 사이에서 실제 예측 제어가 더 낮을 수도 높을 수도 있다
- 손잡이는 공기 가중치 하나만 바꾼다 (NH4 여유는 Park/e52 값으로 고정)
- 예측 제어는 대표 차단과 같은 대리 모델 계열을 쓰고 환경도 같은 계열이다. 검증 구간은 e10 부터 반복해서 썼다
