# Park/e66: 공기량을 묶음마다 직접 맞춘 차단 위 예측 제어와의 짝 비교 (Kaggle DARROW)

상태: **사전 등록 (2026-11-24).** 맞춤 절차, 가설, 판정 규칙은 새 점을 돌리기 전에 정했다. 대표는 이 실험만으로 바꾸지 않는다.

## 목적

Park/e65 는 대표 교체 여부를 팀 결정 사항으로 올리며 "공기량을 다시 맞춘 공정한 비교를 한 번 더 하고 정하기" 를 제안했다. Park/e59 의 곡선 비교는 선형 보간이고, Park/e60 의 학습 구간 고르기는 검증 공기량이 3.6% 어긋나 판정하지 못했다. 이 실험은 Park/e57 이 차단 없는 예측 제어에 쓴 절차 (공기량 정보만으로 묶음마다 공기 가중치를 맞추고 실제로 돌린 짝을 비교) 를 차단 위 예측 제어에 그대로 쓴다.

## 방법

- 기준: `ShortMPC` (`objective='excess'`, NH4 여유 1.2, 1시간) + 대표 차단 (`MinAirBrake(dyn, 3.5, 1, 'others', **BRAKE)`)
- 맞춤: 대표 묶음마다 그 묶음의 검증 공기량 (Park/e35 orig) 을 목표로, Park/e58, e59 의 11개 점 가운데 공기량만 읽어 목표 양옆 두 점의 log(공기 가중치) 를 공기량에 대해 선형 보간한다 (Park/e57 의 `lam_for`). 비용은 읽지 않는다
- 1판 공기량이 목표에서 1% 넘게 벗어난 묶음만, 1판 점을 더해 한 번 다시 맞춘다 (2판). 마지막 판의 값을 쓴다
- 대표는 Park/e35 orig 의 묶음 5개 값을 쓴다

## 평가

검증 40일 x 구성원 5개 = 200 에피소드, 결정적. test 는 쓰지 않는다.

## 가설 (사전 등록)

공기량 차이가 모든 짝에서 ±3% 안일 때만 판정한다 (Park/e43, e57 과 같음). 하나라도 밖이면 둘 다 판정하지 않는다.

- H1. 대표의 하루 비용이 같은 묶음의 차단 위 예측 제어보다 낮은 묶음이 5개 중 4개 이상이고 평균도 낮다
- H2 (반대 방향). 차단 위 예측 제어가 더 낮은 묶음이 4개 이상이고 평균도 낮다

## RESULT.md 처리 (미리 정함)

- H1 지지: "공기량을 묶음마다 맞추면 대표가 차단 위 예측 제어보다 낮다" 고 적고, Park/e59 의 결론을 "곡선 보간에서만" 으로 좁힌다
- H2 지지: "공기량을 묶음마다 맞춰도 차단 위 예측 제어가 대표보다 낮다" 고 적고, Park/e65 의 팀 결정 사항에 근거로 더한다 (대표는 Park 혼자 바꾸지 않음)
- 둘 다 아님: "같은 차단 위에서 학습 정책과 1시간 예측 제어는 공기량을 맞추면 비슷하다" 고 적는다
- 판정 안 함 (맞춤 실패): 값과 공기량 차이를 적는다

## 미리 밝히는 한계

- 공기량 맞춤에 검증 구간의 공기량 정보를 쓴다 (비용은 쓰지 않음). Park/e57 과 같은 조건이다
- 예측 제어와 차단은 같은 대리 모델 계열을 쓰고 환경도 같은 계열이다. 검증 구간은 e10 부터 반복해서 썼다
