# Park/e75: 차단 위 예측 제어의 후보 공기량 간격 (Kaggle DARROW)

상태: **사전 등록 (2026-11-24).** 간격 값, 가설, 판정 규칙은 이 실험의 결과를 보기 전에 정했다. 대표는 바꾸지 않는다.

## 목적

Park/e48 부터 쓴 예측 제어는 첫 스텝 공기량을 500 간격, 나머지 스텝을 1,500 간격으로 둔 후보 133개 가운데 하나를 고른다. 이 간격이 성능을 막고 있는지 (더 촘촘하면 나아지는지), 더 성겨도 되는지 (계산을 줄일 수 있는지) 를 본다. Park/e72 와 같은 틀이다.

## 방법

- 기준: `ShortMPC` (`objective='excess'`, NH4 여유 1.2, 공기 가중치 1.5, 1시간) + 대표 차단. 후보 간격만 바꾼다
- 촘촘하게: 250 / 750 (후보 481개). 성기게: 1,000 / 3,000 (후보 40개). 2번
- 비교: Park/e58, e59 의 기본 설정 곡선 (11개 점) 에서 같은 공기량의 비용 (선형 보간)

## 평가

검증 40일 x 구성원 5개 = 200 에피소드, 결정적. test 는 쓰지 않는다.

## 가설 (사전 등록)

- H1. 촘촘한 간격의 하루 비용이 같은 공기량의 기본 곡선보다 0.05 넘게 낮다
- H2. 성긴 간격의 하루 비용이 같은 공기량의 기본 곡선보다 0.05 넘게 높다
- 공기량이 곡선 범위 밖이면 그 가설은 판정하지 않는다

## RESULT.md 처리 (미리 정함)

- H1 지지: "후보를 촘촘하게 하면 차단 위 예측 제어가 더 낮아진다" 고 적는다. 기각: "후보 간격 500 / 1,500 은 성능을 막지 않는다" 고 적는다
- H2 지지: "후보 간격 1,000 / 3,000 은 너무 성기다" 고 적는다. 기각: "후보 40개로도 같은 성능이다 (계산을 줄일 수 있음)" 고 적는다

## 미리 밝히는 한계

- 점 하나씩의 비교다. 차이 기준 0.05 는 Park/e72 와 같다
- 공기 가중치는 다시 맞추지 않는다 (곡선 비교로 다룸). 검증 구간은 e10 부터 반복해서 썼다
