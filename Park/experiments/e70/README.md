# Park/e70: 대표 차단 위의 ABAC 와의 같은 공기량 비교 (Kaggle DARROW)

상태: **사전 등록 (2026-11-24).** 설정값, 곡선 규칙, 가설은 이 실험의 결과를 보기 전에 정했다. 대표는 바꾸지 않는다.

## 목적

Park/e65 는 이득의 원천을 "차단 위에서 공기를 덜 쓰는 제어기" 로 고쳤고, 그 제어기가 학습 정책일 필요는 없다고 적었다 (예측 제어도 됨). 그렇다면 대리 모델을 쓰지 않는 가장 단순한 현장 제어기 ABAC 도 차단 위에 두면 대표만큼 하는가. 이 실험은 차단 위 제어기에 무엇이 필요한지 (모델 기반 계획 또는 학습 대 단순 피드백) 를 가른다.

## 방법

- 차단 + ABAC: 다시 고른 ABAC (Park/e54, Kp 4,000, Ki 1,600) 에 대표 차단을 씌운다
- 설정값 2.6, 3.2, 3.8, 4.4, 5.0 (3.2 는 Park/e54 고른 값) 으로 검증 구간 곡선을 만든다. 설정값이 높을수록 공기를 덜 쓰고, NH4 한도는 차단이 지킨다
- 곡선과 판정 규칙은 Park/e58 과 같다 (지배되는 점을 빼고 선형 보간, 범위 밖 묶음은 "대표가 낮지 않음")
- 대표는 Park/e35 orig 의 묶음 5개 값을 쓴다

## 평가

검증 40일 x 구성원 5개 = 200 에피소드, 결정적. test 는 쓰지 않는다.

## 가설 (사전 등록)

- H1. 대표 묶음 5개 모두 곡선 범위 안이고, 대표의 하루 비용이 같은 공기량의 "차단 + ABAC" 곡선 비용보다 낮은 묶음이 4개 이상이며 평균도 낮다
- H2 (반대 방향). 5개 모두 범위 안이고, 곡선이 대표보다 낮은 묶음이 4개 이상이며 평균도 낮다

## RESULT.md 처리 (미리 정함)

- H1 지지: "차단 위 제어기는 아무것이나 되지 않는다. 단순 피드백 (ABAC) 은 차단 위에서도 대표보다 높다" 고 적고, 기여 분리의 "차단 위의 제어기" 를 "차단 위의 모델 기반 또는 학습 제어기" 로 좁힌다
- H2 지지: "차단 위에서는 단순 ABAC 도 대표보다 낮다" 고 적고 이득의 원천을 "차단" 쪽으로 옮긴다
- 둘 다 아님: "차단 위에서는 ABAC 도 대표와 비슷하다" 고 적는다

## 미리 밝히는 한계

- Kp, Ki 는 차단 없이 고른 값이고 차단 위에서 다시 고르지 않는다 (ABAC 에 불리할 수 있음)
- 곡선은 검증 구간에서 만든 것이라 ABAC 에 유리하다. 검증 구간은 e10 부터 반복해서 썼다
