# e113 희귀 NH4 상승 날짜를 정책 학습에서 두 배로 뽑는 실험

## 비교 방법

동일한 DARROW 공통 환경 v1.1에서 동일한 FCSRL + PPO-Lag와 Actor 출력 보정을 학습했다. 날짜를 뽑을 때 균등 조건은 날짜마다 표 한 장, 재표본화 조건은 희귀 상승이 있는 날에만 한 장을 더 준다. 각 에피소드는 선택된 날짜의 초기 상태, 유입, 온도 및 시간 순서를 유지한다. 그날의 이후 수질은 정책 행동에 따라 모의된다. 두 정책 모두 희귀일 표시를 관측하지 않는다. [사전 설계와 문헌](REFERENCES_AND_DESIGN.md)

| 역할 | 기간 | 날짜 수 | 사용 방법 |
| --- | --- | ---: | --- |
| 정책 학습 | 2021-05-06 ~ 09-22 | 140 | 희소성 계산과 두 조건의 정책 갱신 |
| 가을 평가 | 2021-09-23 ~ 11-09 | 48 | 양쪽의 정책 갱신에서 제외한 주 평가 |
| 겨울 평가 | 2021-11-10 ~ 12-19 | 40 | 반복 사용한 개발 날짜에서 전이 확인 |

48일은 정책 학습용 날짜 추출에서 빠졌으며, 공유 모델 준비에는 일부 또는 전부 사용됐다. e30 준비 코드를 다시 확인하면 GBM은 원래 188일로 학습했다. 모방 초기 정책은 앞 150일로 적합하고 뒤 38일로 오차를 확인했으며 최종 40번째 가중치를 저장했다. 정규화기는 앞 150일에서 적합했다. 따라서 가을 48일 중 처음 10일이 초기 정책과 정규화기 적합에 포함됐다. 팀 시험 구간은 평가하지 않았다. [기준 모델 준비 코드](../e30/prepare.py)

실측 NH4 상승 시작 1,007건에서 다른 학습일의 가장 가까운 실측 상태까지 거리를 계산했다. 11개 관측의 학습 IQR로 나눈 RMS 거리 90분위 0.359305를 엄격히 초과한 101건은 53일에 분포했다. 이 날짜들의 이론적 선택 비율은 균등 53/140, 재표본화 106/193이다. 실제 모의 경로에서 위험 사건이 반드시 발생하는 날짜로 해석할 수 없다.

## 재현 및 검산

사전 설계 283fd48, 학습 실행 72dc313. e30의 기본 호출 동작을 보존하고 입력 날짜 목록과 동일 전이 추론기를 호출 시 지정할 수 있도록 했다. Lee의 수치 추론 모듈은 저장소 10b477a의 Lee/code/darrow/fast_gbm.py와 동일하다. PyTorch 2.14.1+cu130의 CPU 경로, NumPy 1.26.4, scikit-learn 1.9.1, pandas 2.2.3, Numba 0.63.1 및 llvmlite 0.46.0을 사용했다. 정책 seed 0~4에 각 401,280전이, 마지막 정책, 전이 95개로 구성된 운전일과 환경 구성원 5개를 동일 가중한다. 총 공기량 단위는 Nm³/23.75h다.

학습 전 입력 해시 7개를 e50과 대조하고, 학습일 7개에서 구성원 5개와 무작위 행동 95스텝의 상태, 관측, 보상, 비용이 원 sklearn 추론과 원소별로 같은지 확인했다. 독립 전수 거리 계산으로 1,007건의 거리와 53개 날짜 집합도 검산했다. 마지막 정책 검증은 원 sklearn 경로에서 수행한다.

서버 원시는 /home/jio/fcsrl_src/results/e113/main 이며 plan.json에 분할, 희귀 날짜, 입력 해시가 있고 각 실행 폴더에 날짜 추출 횟수, 학습 로그, 마지막 정책, 날짜와 구성원별 모의 경로가 있다.

```sh
# 저장소 루트에서 실행. 준비 단계는 새 출력 폴더를 생성한다.
py=/home/jio/fcsrl_src/.venv-skl191/bin/python
exp=Yoo/experiments/e113
out=/home/jio/fcsrl_src/results/e113/replay
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OMP_WAIT_POLICY=PASSIVE
export PYTHONPATH=/home/jio/fcsrl_src/results/e113/accel-deps
"$py" "$exp/run.py" "$out"
for arm in uniform weighted; do
  for seed in 0 1 2 3 4; do
    "$py" "$exp/run.py" "$out" --arm "$arm" --seed "$seed"
  done
done
"$py" "$exp/report.py" "$out" "$out/tables"
```
