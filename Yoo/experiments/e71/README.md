# e71: e70 학습 연장 (갱신 500번)

**상태: 실행 중 (2026-11-18 시작).** [사전 조건](protocol.json), [실행](run71.py), [집계](report71.py). 학습 코드는 [e70/train70.py](../e70/train70.py) 를 바꾸지 않고 쓴다.

## 왜 하는가

[e70](../e70/README.md) 에서 PID 승수 이득을 한도 비율 (25 / 0.3) 로 맞추고 적분 상한을 묶자, 같은 갱신 250번에서 dev 한도 0.3 충족이 FCSRL 0/10 에서 6/10, 고정 표현 PPO 1/10 에서 3/10 으로 늘었다. 사전 기준 8/10 에는 못 미쳤지만 FCSRL 미달 4개 중 3개가 0.32 ~ 0.34 였고, 학습 수집 비용은 마지막까지 0.31 에서 0.29 로 내려가고 승수는 상한 근처 (약 19) 에서 막 내려오기 시작했다.

갱신 수만 늘려 한도 충족이 8/10 에 닿는지, 승수가 내려오며 공기가 다시 줄어드는지, 그때도 FCSRL 의 우세가 남는지 본다. 같은 seed 라 처음 250번은 e70 과 같아야 하므로 학습 로그 전체 수치로 재현 검사를 한다.

## 해석상 주의

- 500번은 우리 자원 배정이며 수렴을 보장하는 양이 아니다. 실패하면 이 예산에서 해결되지 않았다고만 쓴다.
- dev 는 학습과 조정, val 은 반복 사용한 개발 자료다. holdout 은 과거 개발 자료여서 독립 미노출 시험이 아니다.
- 모든 결과는 대리 환경 안의 비교이며 현장 절감이 아니다.
