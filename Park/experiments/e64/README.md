# Park/e64: 새 기준에 대한 날짜 블록 불확실성 (Kaggle DARROW)

상태: **사전 등록 (2026-11-21).** 가설과 판정 규칙은 Park/e60 의 검증 결과와 이 실험의 결과를 보기 전에 정했다. 대표는 바꾸지 않는다.

## 목적

Park/e49 는 날짜 블록 다시 뽑기로 대표 대 e43 ABAC 의 비용 차이 구간을 냈다. 그 뒤 Park/e54 에서 ABAC 를 다시 골라 이득이 0.79 에서 0.54 로 줄었고, Park/e55 는 새 기준의 날짜 블록 구간을 "다시 계산하지 않음" 으로 남겼다. 또 Park/e58, e60 의 차단 위 예측 제어가 새 비교 대상이 됐다. 이 실험은 두 새 기준에 대해 e49 와 같은 날짜 블록 구간을 낸다.

## 방법

- 다시 고른 ABAC (Park/e54: 설정값 3.2, Kp 4,000, Ki 1,600) 와 차단 위 예측 제어 (Park/e60 고름) 를 스텝 기록 (`rollout_log`) 과 함께 검증 구간에서 돈다
- 대표의 스텝 기록은 Park/e44 (묶음 5개) 를 쓴다
- 다시 뽑기는 Park/e49 와 같다: 날짜마다 구성원 5개 평균 (대표는 묶음 5개도 평균), 날짜 단위 짝 차이, 이어진 5일 원형 이동 블록, 10,000번, seed 0, 95% 백분위

## 평가

검증 40일 x 구성원 5개 = 200 에피소드, 결정적. test 는 쓰지 않는다.

## 가설 (사전 등록)

- H1. 대표 빼기 다시 고른 ABAC 의 날짜 평균 비용 차이의 블록 95% 구간이 0 아래다
- H2 (방향을 정하지 않은 구분). 대표 빼기 차단 위 예측 제어의 블록 95% 구간이 0 아래면 "대표가 낮음", 0 위면 "예측 제어가 낮음", 0 을 포함하면 "차이 없음" 으로 적는다

## RESULT.md 처리 (미리 정함)

- H1 지지: "다시 고른 ABAC 대비 이득도 날짜 블록 구간에서 0 을 넘지 않는다" 고 적는다. 기각이면 "다시 고른 ABAC 대비 이득은 날짜 단위로 보면 확실하지 않다" 고 주 주장의 한계에 적는다
- H2: 세 구분 가운데 하나를 그대로 적는다

## 미리 밝히는 한계

- 검증 40일 한 계절이라 블록이 8개뿐이다. 검증 구간은 e10 부터 반복해서 썼다
