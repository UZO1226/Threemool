# e43: 상태 피드백과 전체 제어 구조 감사

2026-11-10. e42 이후 승인된 전체 구조 검토다. 새 정책이나 대리 모델 학습 대신 기존 코드의 피드백, 관측 누락, 날짜 경계를 검사한다. DARROW, 총 공기량 행동, FCSRL의 dynamics/feasibility 표현과 공기/NH4/DO 동시 개선 목표를 유지한다.

## 실행 전 고정 범위

- e30 데이터의 train188일만 진단한다. val40/test41은 평가하지 않는다.
- e35 DO 대응 수정 모델을 고정한다. e38~e42 미채택 모델을 제어 환경에 넣지 않는다.
- 첫 train 날짜에서 기존 평가 함수를 사용해 95회 정책 호출과 상태 전달을 검사한다. 미래 실측 수질을999로 바꿔도 경로가 완전히 같은지 확인한다. 정책은 학습 정책이 아닌 고정 진단 함수다.
- 모든 train 날짜의 t=1,48,94에서 같은 정책 관측과 같은 총 공기량을 유지하고, 현재 배분/직전 구간 유량/누락 유입 성분을 각각 다른 train 날짜의 값으로 교체한다. 이는 모델의 입력 의존성을 확인하는 합성 검사이며 현실에서 가능한 개입이나 제어 개선의 근거가 아니다.
- GAE와 feasibility의 날짜 경계에서 다음 날 항은 끊고 마지막 상태 가치 bootstrap은 남는지 수치 검사한다.
- 기존 관측11개에 직전 실행 구간 유량5개를 추가한 16차원 관측 함수를 작성하고 인과적 읽기 범위를 검사한다. 첫 스텝 추가5개는0으로 마스킹한다. 기존 환경/학습기에는 연결하지 않는다.

가설은 정책에 이미 피드백이 있지만 물리 대리 환경의 자기 예측과 관측 누락이 별개로 존재한다는 것이다. 원인을 하나로 확정하거나 공기 절감 성능을 측정하는 실험이 아니다. 결과와 다음 설계는 실행 후 아래에 기록한다.

## 검토 결론

**정책은 이미 15분마다 피드백한다. 문제는 모델이 만들어 낸 상태를 피드백한다는 점과 정책에 일부 운전 정보가 빠져 있다는 점이다.** 센서 피드백을 새로 붙이면 해결된다는 설명은 맞지 않는다. 이번 감사로 전체 성능 악화의 단일 주원인을 확정하지 않았다.

현재 연결은 다음과 같다.

```text
실측 하루 첫 상태
  -> 관측11개
  -> FCSRL 표현 + PPO Actor -> 총 공기량
  -> 기록의 구간 배분으로 공기량 분배
  -> 별도 GBM 대리 환경 -> 다음 수질 예측
  -> 관측11개로 돌아가 다시 행동 선택 (95회)

FCSRL의 보조 dynamics/feasibility 표현 학습
  <- 위 전이와 비용으로 학습
  != 실제 수질을 만드는 GBM 대리 환경
```

FCSRL 원래 역할은 안전 관련 표현을 학습하는 것이다. 대리 환경의 잘못된 물리 전이를 자동으로 교정하는 장치는 아니다. 원 구현의 표현 학습을 유지한 채 정책 입력을 보완하는 것은 적용 설계 변경이며, 그 자체를 새로운 FCSRL 알고리즘이라고 주장하지 않는다. [FCSRL 원 논문](https://proceedings.mlr.press/v235/cen24b.html).

| 부분 | 현재 코드 | 검토 결과 |
| --- | --- | --- |
| 행동 선택 | e33 `evaluate`/`collect`에서 매 스텝 호출 | 하루 행동을 한 번에 선택하는 개방 제어가 아님 |
| 수질 상태 | e30 `BatchEnv.step`의 GBM 예측을 다음 입력으로 사용 | 실제 관측은 reset 시 첫 상태만 사용 |
| 학습 수집 길이760 | 95전이짜리 하루8개를 이어 수집 | 물리 환경을760회 연속 예측하는 것이 아님 |
| 외부 조건 | 기록된 유입/수온/구간 배분을 해당 시각에 재생 | 대체 정책에서도 이 일정이 유지된다는 조건부 시뮬레이션 |
| Actor 정보 | 상태5개, 유입량, 온도, 시각2개, 유입NH4, 이전 총 공기량 | 현재 배분, 이전 구간별 유량, 유입 성분4개는 빠짐 |
| 물리 모델 입력 | 상태5 + 외부조건9 + 현재구간5 + 이전구간5 | 같은 정책 관측에서도 숨은 입력에 따라 다음 상태가 달라짐 |
| 날짜 경계 | GAE/표현 목표 사슬은 끊고 마지막 상태 가치 유지 | 다음 날 보상이 직접 섞이는 버그는 검사에서 없음 |
| 목표 시간 | gamma0.99, feasibility 할인0.9, PID/보고는 비할인 합 | 유한 하루 부피/비용과 정확히 같은 목적은 아님 |

초기 `prev_air/prev_zone`은 전날 마지막 기록이 아니라 당일 첫 행으로 채운다. 이를 제어기 진입 직전 운전 상태로 볼 수 있다는 가정이 들어 있다. 원자료가 명령 전 순간값인지 구간 평균인지까지 이번 감사로 확인하지 않았다. 관측 후보의 인과적 불변 검사는 t>=1에 한정한다. 후속 대조에서는 추가5개를 첫 스텝에0으로 마스킹하고, 원래11개에 남은 초기 총 유량 가정은 두 군에 동일하게 명시한다.

## 실행 결과

최종 실행 커밋 `b9e0e91`, 11.53초, CPU1스레드. Python3.10.19, numpy1.23.5, sklearn1.7.2의 기존 환경을 사용했다. 입력 및 소스 SHA256은 [audit.json](audit.json), 원 출력은 `/home/jio/fcsrl_src/results/e43/masked/audit.json`이다. 새로운 학습, 검증40일/테스트41일 성과 평가는 없다. 준비 pickle에는 모든 분할이 들어 있지만 진단 대상은 train188일뿐이다.

1. 기존 평가 함수에서 상태를 읽는 진단 정책이95회 호출됐다. 매번 정책 입력의 수질5개가 직전 모델 상태와 일치했다. 미래 실측 수질을 모두999로 바꿔도 관측/최종 상태/집계가 완전히 같았다. 이는 미래 실측 수질을 읽지 않는다는 검사이며 미래 외부조건 재생까지 없다는 뜻은 아니다.
2. 날짜 경계 뒤 보상을999로 바꿔도 직전 날짜 GAE/feasibility 목표는 같았다. 마지막 보상2, 다음 가치10의 예에서 GAE 이점은11.9, feasibility는9였다. bootstrap을 유지하는 현재 코드와 일치한다. 마지막94번째 시점 할인은 보상/비용 가치0.389, feasibility 약0.000050으로 서로 다르다. 원 feasibility는 할인 max 위험 목표이므로 일일 누적 비용과 같은 수치여야 한다는 의미는 아니다.

## 무엇을 바꾸면 안 되는가

기록된 미래 수질은 역사적 공기 행동의 결과다. 새 정책 행동을 실행한 뒤 그 실측값으로 상태를 덮으면 새 행동의 영향이 지워진다. 센서 재주입 후 낮은 비용을 대체 정책의 제어 성과라고 보고하지 않는다. e35의 실측DO 주입도 모델 경로를 분해하는 oracle 진단이었다.

실측에서 짧게 분기하는 방법은 검토 가치가 있다. MBPO는 실제로 경험한 상태에서 짧은 모델 경로를 생성해 누적 오차를 제한하며, 원 구현은 off-policy 최적화를 사용한다. [저자 설명과 원 논문/구현 연결](https://bair.berkeley.edu/blog/2019/12/12/mbpo/). 현재 연구는 고정된 과거 자료와 PPO를 사용하므로 그대로 붙일 수 없다. PPO 데이터 수집/이전 정책 확률, 분기 상태 분포, 경계 가치, 제약 PID를 함께 정의해야 한다. 짧은 경로의 비용을95배로 늘려 하루 안전성을 추정하는 것도 정당화되지 않는다. 이번에는 그 설계 변경을 하지 않는다.

현재 구간 배분을 추가하면 더 많은 정보를 제공할 수 있지만, 이 값은 실제 같은 시각의 기록 공기량에서 계산한다. 상위 배분기가 총량 선택 전에 비율을 알려준다는 자료 근거가 없다. 바로 입력에 넣으면 실제 제어에서 얻지 못하는 정보를 준 실험이 될 수 있다. 또한 대체 정책에서도 기록 배분이 유지된다는 환경 가정이 해결되지 않는다. 현재 비율의 사전 가용성이 확인되기 전에는 첫 후보에서 제외한다. 보간한 유입 성분도 새로운 온라인 센서라고 취급하지 않는다.

## 다음으로 정한 대조

**직전 실행 구간별 공기량을 정책에 제공하는 관측 대조를 먼저 한다.** 총량만으로는 어느 구간에 공기가 공급됐는지 알 수 없다. 직전 실행 명령은 새 센서나 미래 정답 없이 제어기가 기억할 수 있는 정보다. 이는 e34에서 남아 있던 관측 보완을 제한된 범위로 실행하는 것이며, 환경 실패를 해결했다고 주장하는 우회로가 아니다.

| 항목 | 고정할 설계 |
| --- | --- |
| 환경 | e35 수정 GBM, 동일 DARROW train188/개발val40, test41 미사용 |
| 비교 | PPO, FCSRL, FCSRL Actor 보정 각각 기존 관측 대 보완 관측 |
| 입력/용량 대조 | 두 군 모두16차원. 기준은 원11개+0다섯 개, 후보는 원11개+직전 실행 구간5개/9000. 첫 전이는 추가5개를0으로 둠 |
| 모방 prior | 두 군 모두 기존 동일11개만 입력, 동일 가중치 고정. 새 정보로 BC를 다시 학습하지 않음 |
