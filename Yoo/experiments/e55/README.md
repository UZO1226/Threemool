# e55: 저온 지원 범위와 NH4 반복 예측 오류 검산

2026-11-13 완료. [결과 표](results.md), [원 수치](results.json), [진단 조건](protocol.json), [실행 코드](audit.py).

## 목적과 범위

Yoo README를 현재 상태 중심으로 정리한 뒤, 다음 환경 변경을 결정하기 전에 사용자가 전달한 겨울 진단을 검산했다. 질문은 학습 범위 밖 저온이 존재하는지, NH4 예측 오류가 그 구간에 집중되는지, 모델의 온도 반응이 일관되게 반대 방향인지다.

기존 e45는 정책의 날짜별 조건 차이를 다뤘다. 이번에는 기록 행동으로 만든 같은 상태 예측 경로와 실제 NH4 정답을 대조해 환경 오차를 분리했다. 새 정책, grey-box, 대리 모델 재학습 또는 공통 환경 변경은 없다. 사용자에게 전달된 새 진단의 원 실행 파일은 확인하지 못해, 기존 준비물과 저장 경로로 독립 계산했다.

## 조건과 실행

- 데이터: Kaggle DARROW의 e30 준비물. train188일, 개발 val40일. 원 pickle은 test를 포함하지만 train/val 행만 추출하고 test 행은 평가하지 않는다. 시험 구간 수온 범위도 이번 작업에서는 재계산하지 않았다.
- 모델: e35 DO 구간 대응 수정 GBM, scikit-learn 1.7.2. e50 공통 v1.1 모델과 다르다.
- 원 경로: e54 신호 검사의 기록 행동 재생, 날짜당 5구성원 x 95전이. 기존 e53 재생과 배열 일치를 확인한 경로다.
- 온도 구분: 전이 입력 시각 t의 수온을 학습 전이 입력의 최저/최고와 비교한다. NH4 정답은 다음 시각 t+1의 관측값이다. 모델 구성원 5개 경로를 독립 실제 사건으로 해석하지 않는다.
- 비용 여유 없음. NH4>4인지를 비교한다. MAE 단위는 mg/L이며 부호 있는 오차는 예측−실측이다. FPR 분모는 실제 정상, 탐지율 분모는 실제 위반이다.
- 실측 상태 한 스텝 예측과 하루 자기 예측 경로를 구별한다. 실측 상태를 매번 주는 진단을 새 자율 제어 성능으로 쓰지 않는다.
- 기초 실행 커밋 `ec82495`, 12.74초. 결과를 본 뒤 비단조 반응과 당일 저온 노출 이력을 추가한 탐색 후속 커밋 `43d6e01`, 44.43초. 최종 표는 후속 실행이며 최초 출력도 보존한다. 모두 사전 확증 실험이 아닌 탐색 진단이다.

## 확인한 사실

1. 학습 수온은 14.018~28.421°C, 개발 수온은 9.443~20.597°C다. 개발 3,800전이 중 474개(12.47%)가 학습 최저 수온 아래다. 실제 해당 입력과 수온만 14.018°C로 올린 입력의 NH4 변화량 예측 차이는 모든 구성원에서 0이다. 저온 구간을 구별하지 못하는 한계는 확인됐다.
2. 저온 전이의 반복 NH4 MAE는 3.825로 범위 안 2.714보다 높다. 하지만 전체 절대오차의 83.28%, 놓친 위반의 80.41%는 현재 수온이 범위 안인 곳에서 발생한다. 이는 위치별 집계이며 저온의 인과 기여율은 아니다.
3. **하루 95전이 내내 학습 최저 수온 이상인 검증 27일에서도 반복 예측이 나쁘다.** 한 스텝 MAE 0.279→반복 2.508, FPR 2.38→24.52%, 탐지율 88.78→49.50%다. 전이 입력의 범위 밖 저온만으로 전체 실패를 설명하기 어렵다. 과거 날짜의 생물학적 이력이나 다른 변수의 지원 범위는 통제하지 않았다.
4. 온도 반응은 단순한 역방향이 아니라 비단조다. 다른 입력을 고정하고 14.018→16.076°C로 올리면 개발 입력의 평균 NH4 변화량은 +0.0619→+0.1087 mg/L로 증가한다. 반면 학습 사분위 18.237→21.163°C에서는 평균 변화량이 0.01664 mg/L 감소하며 구성원/입력의 75.56%가 감소 방향이다. 모든 온도에서 방향이 반대라는 주장은 지지하지 않는다. 관측되지 않은 입력 조합도 포함될 수 있어 이를 실제 질산화 반응률의 인과 추정으로 쓰지 않는다.
5. 기록 행동에서 개발 전체 반복 NH4 편향은 +1.939 mg/L다. 이 경로에서는 평균 과대예측이지 일괄 과소예측이 아니다. 정책의 다른 행동에서 모델이 낙관하는지 여부는 별도 질문이다. e50의 기록 행동 재생 NH4 28.48%도 실제 관측값과 구분해야 한다.

## 다음 결정

- 저온 외삽 한계를 인정하되, 겨울 온도식 하나로 환경 신뢰성 문제가 해결된다고 전제하지 않는다. grey-box 후보를 만들 때 저온뿐 아니라 범위 안 날짜의 장기 오차, FPR와 놓친 위반, 공기 변화 반응을 함께 통과해야 한다.
- 자유로운 GBM 잔차는 물리 항의 온도 방향을 다시 뒤집을 수 있으므로, 합성된 전체 모델의 방향을 검사한다. 온도 방향을 맞춘 것만으로 새로운 제어 성과를 주장하지 않는다.
- 다음 정책 대조 후보는 동일 코드에서 모방 prior 사용 여부만 바꾸는 것이다. 초기 행동 표준편차 등 다른 설정과 환경은 고정한다. PPO 결과는 구현 선택 진단이며 FCSRL 확장 성과와 구분한다. 이 작업에서는 해당 학습을 시작하지 않았다.
- 불확실성 여유 계열 추가 탐색, 검증 자료의 학습 편입, test 확인, 환경/prior/비용의 동시 변경은 하지 않는다. 기존 FCSRL 핵심과 팀 공통 조건을 유지한다.

## 검증과 재현

입력 파일의 해시를 e54 manifest와 대조했다. 실제 다음 상태와 저장 정답이 정확히 같으며 날짜와 구성원 배열을 정렬했다. 온도 그룹의 표본 수, 혼동행렬과 절대오차 합이 전체와 일치한다. 기초 실행과 후속 실행의 공통 결과는 정확히 같고, 기존 e54의 여유 없는 FPR/탐지율도 정확히 재현했다. 입력 및 코드 해시는 실행 전후 불변이다.

원 출력:

- 최초: `/home/jio/fcsrl_src/results/e55_temperature_audit_20261113/`
- 후속: `/home/jio/fcsrl_src/results/e55_temperature_audit_20261113_followup/`

```bash
cd /home/jio/threemool-temperature-audit
export OMP_NUM_THREADS=1 OMP_WAIT_POLICY=PASSIVE OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
/home/jio/fcsrl_src/.venv/bin/python Yoo/experiments/e55/audit.py --out <존재하지 않는 새 경로>
python3 Yoo/experiments/e55/report.py --root <위 출력 경로>
```

현재 코드는 후속 버전이다. 기초 재현은 `ec82495`를 사용한다. 두 실행은 기존 `.venv`의 CPU 예측만 사용하며 패키지를 변경하지 않았다. 상세 버전과 소스/입력 SHA256은 각 manifest에 있다.
