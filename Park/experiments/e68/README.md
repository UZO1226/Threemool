# Park/e68: 30분 지연에서 대표가 무너지는 곳 나누기, 정책 대 차단 (Kaggle DARROW)

상태: **사전 등록 (2026-11-24).** 가설과 판정 규칙은 이 실험의 결과를 보기 전에 정했다. 대표는 바꾸지 않는다.

## 목적

Park/e62 는 NH4 분석계 30분 지연에서 차단 위 예측 제어가 거의 흔들리지 않는 데 (보정 없이 4.980) 비해 대표는 크게 나빠진다 (Park/e46, 9.623) 는 것을 보였다. 두 방법은 같은 차단을 쓰고 차단도 늦은 NH4 를 보므로, 차이는 차단 위의 제어기에서 온다고 짐작된다 (Park/e62 사후 관찰). 이 실험은 대표에서 지연을 정책에만, 차단에만 따로 주어 어느 쪽이 지연에 민감한지 직접 나눈다.

## 방법

- 지연 d = 2 (30분), 보정 없음. `audit_brake.rollout_log` 와 같은 지표를 내는 rollout 에서 정책이 보는 관측 NH4 와 차단이 보는 관측 NH4 의 지연을 따로 둔다
- "정책만 지연": 정책은 2 스텝 전 NH4, 차단은 지금 NH4. "차단만 지연": 그 반대. 묶음 5개 x 2 = 10번
- 지연 없음은 Park/e35 orig, 둘 다 지연은 Park/e46 (fcsrl_d2) 의 묶음 값을 쓴다

## 평가

검증 40일 x 구성원 5개 = 200 에피소드, 결정적. test 는 쓰지 않는다.

## 가설 (사전 등록)

- H1. 지연 없음 대비 비용 증가가 "정책만 지연" 에서 "차단만 지연" 보다 큰 묶음이 5개 중 4개 이상이고 평균도 크다 (정책이 지연에 더 민감)
- H2. "정책만 지연" 의 증가가 "둘 다 지연" 증가의 절반 이상인 묶음이 4개 이상이다

## RESULT.md 처리 (미리 정함)

- H1 지지: "30분 지연에서 대표가 나빠지는 주된 원인은 학습 정책이 늦은 NH4 를 보는 것이다" 고 Park/e62 옆에 적는다
- H1 기각: "대표가 지연에서 나빠지는 원인은 정책만이 아니다 (차단 쪽 몫이 같거나 크다)" 고 적는다. 이 경우 같은 차단을 쓰는 예측 제어가 왜 덜 나빠지는지는 열린 질문으로 남긴다
- H2 는 H1 과 함께 몫의 크기로 적는다

## 미리 밝히는 한계

- 일정한 순수 지연 하나 (30분) 만 본다. 두 쪽의 상호작용 (둘 다 지연 증가가 두 증가의 합과 다른 것) 은 값으로만 적는다
- 검증 구간은 e10 부터 반복해서 썼다
