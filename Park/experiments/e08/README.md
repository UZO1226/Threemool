# Park/e08: 팀 공식 데이터(Kaggle DARROW) 에서 실행 시점 안전 차단

상태: **완료 (2026-11-10). H1 지지 (NH4 규칙 차단이 5개 seed 모두 하루 비용을 줄임), H2, H3 지지 안 됨.** 규칙은 학습 전에 정했고 결과를 본 뒤 바꾸지 않았다.

## 목적

팀 공식 데이터인 Kaggle DARROW 대회 자료(사용자 확인, 2026-11-10) 에서, BSM1 (Park/e01 ~ e06) 과 Avedøre (Park/e07) 에서 시험한 실행 시점 안전 차단을 다시 시험한다.

Park/e07 에서는 Avedøre 대리 모델이 NH4 가 높은 순간 공기를 더 넣으면 NH4 가 덜 내려가는 반대 반응을 보여 모든 차단이 실패했다. Lee/e07 은 DARROW 에서 같은 문제(운전 기록의 교란을 인과로 배움) 를 확인하고, 공기량이 늘면 NH4 변화량은 비증가, 구간 DO 는 비감소하도록 강제한 단조 제약 GBM 대리 모델을 썼다. 따라서 DARROW 는 차단이 물리적으로 말이 되는 방향에서 시험되는 환경이다.

### 환경 검사에서 찾은 Lee 환경의 작은 문제

Lee 의 `env_dw.py` 는 하루가 끝난 환경을 reset 할 때 `prev_air[i]` 를 다음 에피소드의 첫 기록 공기량으로 덮어쓴다. 이 배열이 그 스텝의 `info['air']` 와 같은 객체라서, 마지막 스텝의 공기량(과 보상) 이 다음 에피소드 첫 공기량으로 바뀐다. 비용과 위반율에는 영향이 없고, 하루 공기량 합계가 하루 95 스텝 중 1 스텝만큼 달라진다. 이 차이를 반영하면 Lee 코드 결과와 정확히 같다. 내 환경은 실제 공기량을 센다.

## 단계

| 단계 | 내용 |
| --- | --- |
| 0 환경 검사 | 완료, 모두 통과 (위) |
| 1 정책 학습 | FCSRL + PPO-Lag, seed 0 ~ 4. Lee/e07 과 같은 설정: 환경 8개 x 760 스텝 x 66 갱신 = 401,280 전이, 갱신마다 대리 모델 구성원 하나를 골라 모든 환경이 같이 쓴다, log std 초기 -0.5, 한도 12, PID 0.02 / 0.005 / 0.01, 상한 20. 마지막 정책만 쓴다 |
| 2 사전 점검 | 차단이 걸리는 순간(NH4 측정값 >= 3) 같은 상태에서 정책 공기량과 차단 공기량을 대리 모델에 넣어 다음 스텝 NH4 를 비교한다 (e07 사후 진단과 같은 방법). 보고만 한다 |
| 3 차단 평가 | 검증 40일 x 구성원 5개 = 200 에피소드를 결정적으로 돈다. test 는 쓰지 않는다 |

## 차단 (Park/e07 과 같은 구조)

실행 공기량 = max(정책 공기량, 차단 공기량). 차단 공기량은 학습 구간 기록 총 공기량의 90% 분위수(5,807) 를 반올림한 **5,800 Nm3/h** 다.

| 차단 | 설정 (곡선) |
| --- | --- |
| NH4 규칙 (NH4 측정값 >= theta 이면 5,800) | theta 2.0, 2.5, 3.0, 3.5, 4.0 |
| 예측기 켜고 끄기 (p >= 기준이면 5,800) | 기준 0.05, 0.1, 0.2, 0.3, 0.5, 0.7, 0.9 |
| 예측기 비례 (5,800 x min(1, p / c)) | c 0.1, 0.25, 0.5, 1.0 |

예측기: 관측 11개와 하루 중 시각 2, 3배 주기 sin, cos 4개를 쓰는 로지스틱 회귀. 정답은 "다음 4 스텝(1시간) 안에 NH4 > 4". 정책마다 차단 없이 학습 구간에서 돈 궤적(정해진 난수 seed 7000 + 정책 seed 로 고른 300 에피소드) 으로 맞춘다. 표준화, L2 1e-3, 뉴턴법 50회.

## 지표와 비교

e07 과 같다. 하루 공기량, 하루 비용, NH4 위반 %, DO 위반 %, 한도 12 만족 %, 개입 %. 같은 공기량 차이는 비교 곡선을 공기량 순으로 이은 선형 보간 하루 비용을 뺀 값의 정책 평균이다. 음수면 앞 곡선이 낫다.

## 가설 (사전 등록)

FCSRL 정책 seed 5개 중 3개 이상에서 성립하고 seed 평균도 성립하면 지지로 적는다. 비교 점이 없는 seed 는 성립하지 않은 것으로 센다.

- H1. NH4 규칙 theta 3.0 차단의 하루 비용이 차단 없음보다 낮다 (단조 제약 환경에서는 차단이 비용을 줄이는가. e07 에서 기각됨)
- H2 (주 가설). 예측기 켜고 끄기 곡선의 같은 공기량 차이가 NH4 규칙 곡선 대비 음수다
- H3. 예측기 비례 곡선의 같은 공기량 차이가 예측기 켜고 끄기 곡선 대비 음수다

가설이 기각되는 결과도 그대로 기록한다. 학습된 정책의 성능은 Lee/e07 의 마지막 모델과 나란히 보고하되 판정하지 않는다.

## 미리 밝히는 한계

- 대리 모델의 예측 정확도가 낮다 (Lee/e07: 하루 평균 NH4 상관 0.29, NH4 위반을 실제보다 많이 예측). 절대 수치보다 방법 간 비교로 읽는다
- 검증 구간은 겨울이고, 기록된 운전조차 하루 비용 28.77 로 한도 12 를 크게 넘는다
- 단조 제약 때문에 차단이 NH4 를 줄이는 방향은 모델 구조로 보장된다. 차단 효과의 크기는 대리 모델에 달려 있다
- 차단 공기량 5,800 하나만 본다. seed 5개, 401,280 전이, 마지막 정책의 탐색적 실험이다
- 대회 자료의 약관은 확인하지 못했다 (Lee 와 같음). 자료는 저장소에 넣지 않는다

## 실행 명령

```bash
D=Park/data/darrow   # 사용자가 내려받은 zip 을 풀어 둔 곳 (Git 제외)
export OMP_NUM_THREADS=1 WANDB_MODE=disabled   # scikit-learn 1.9.1, pandas 2.2.3
python Lee/code/darrow/prep_darrow.py --csv $D/train_val_test_online_dataset.csv --influent $D/train_val_test_dynamic_influent.csv --out $D/darrow_15min.pkl
python Lee/code/darrow/surrogate_dw.py --data $D/darrow_15min.pkl --out_mlp $D/darrow_surrogate_mlp.npz --out_gbm $D/darrow_surrogate_gbm.pkl --report $D/darrow_surrogate_report.json
python Lee/code/darrow/calibrate_dw.py --data $D/darrow_15min.pkl --surrogate $D/darrow_surrogate_gbm.pkl --out $D/darrow_calibration.json
cd Park/code
python check_darrow.py --data ../data/darrow/darrow_15min.pkl --surrogate ../data/darrow/darrow_surrogate_gbm.pkl --calibration ../data/darrow/darrow_calibration.json --out ../experiments/e08/check_darrow.json
for s in 0 1 2 3 4; do python train_darrow.py --method fcsrl --seed $s --data ../data/darrow/darrow_15min.pkl --surrogate ../data/darrow/darrow_surrogate_gbm.pkl --out <결과>/dw_runs/fcsrl_s$s; done
cd ../experiments/e08
for s in 0 1 2 3 4; do python run_e08.py one --seed $s --data ../../data/darrow/darrow_15min.pkl --surrogate ../../data/darrow/darrow_surrogate_gbm.pkl --runs <결과>/dw_runs --out <결과>/e08; done
python run_e08.py report --out <결과>/e08 --runs <결과>/dw_runs --md results.md
```

다시 만든 대리 모델의 정확도 지표와 공기량 반응은 Lee/e07 표와 같았다 (예: NH4 한 스텝 R2 0.242, 하루 평균 NH4 상관 0.293, 공기 0.5 ~ 1.5배에서 NH4 8.78 에서 1.04). 전처리 pickle 과 대리 모델 pickle 의 sha256 은 패키지 버전 차이로 Lee 기록과 다르다. 실제 운전 재생 하루 비용은 학습 12.18 (Lee README 12.17), 검증 28.77, 평가 8.80 이다.

## 실행 결과

전체 표는 [results.md](results.md).

### 단계 1: 학습된 정책 (검증 200 에피소드, 마지막 정책, seed 5개)

| 방법 | 공기량 Nm3/일 | 하루 비용 | NH4 위반 % | DO 위반 % | 한도 만족 % |
| --- | --- | --- | --- | --- | --- |
| FCSRL + PPO-Lag (이 실험) | 77,266 | 13.66 | 13.34 | 1.03 | 77.2 |
| FCSRL + PPO-Lag 마지막 모델 (Lee/e07) | 77,567 | 18.53 | 18.83 | 0.67 | 66.3 |
| 실제 운전 재생 | 84,860 | 28.77 | 28.48 | 1.80 | 해당 없음 |

공기량은 Lee/e07 과 거의 같고 비용은 조금 낮다. seed 2 가 24.53 으로 높아 seed 사이 편차가 크다 (표준편차 5.50).

### 단계 2: 사전 점검

차단이 걸리는 순간(NH4 측정값 >= 3) 같은 상태에서 공기를 5,800 으로 올리면, 5개 seed 모두 다음 스텝 NH4 가 정책 공기량일 때보다 낮았다 (더 높은 경우 0%). 단조 제약 대리 모델에서 기대한 대로이며, Park/e07 의 Avedøre 대리 모델(75 ~ 84% 에서 반대) 과 대조된다.

### 단계 3: 차단 (정책 평균)

| 조건 | 공기량 | 하루 비용 | NH4 위반 % | DO 위반 % | 한도 만족 % |
| --- | --- | --- | --- | --- | --- |
| 차단 없음 | 77,266 | 13.66 | 13.34 | 1.03 | 77.2 |
| NH4 규칙 theta 3.0 | 91,279 | **6.62** | 5.04 | 1.93 | 87.1 |
| NH4 규칙 theta 4.0 | 88,611 | 8.88 | 7.47 | 1.88 | 81.3 |
| 예측기 켜고 끄기 0.1 | 89,513 | 6.62 | 5.23 | 1.74 | 87.0 |
| 예측기 비례 c 0.1 | 90,880 | 6.27 | 4.96 | 1.65 | 88.1 |

### 사전 등록 가설 판정

- H1 지지. NH4 규칙 theta 3.0 은 5개 seed 모두 하루 비용을 줄였다 (평균 -7.04, seed 별 -2.83 ~ -17.08). 공기량은 평균 14,013 Nm3/일 (18%) 늘었다.
- H2 지지 안 됨. 같은 공기량에서 예측기 켜고 끄기가 NH4 규칙보다 비용이 낮은 seed 는 2/5, 평균 +0.20 이다.
- H3 지지 안 됨. 비례가 켜고 끄기보다 낮은 seed 는 1/5 (seed 2 의 -6.80 이 평균을 -0.83 으로 끌어내렸다).

### 해석

- 공기를 넣으면 NH4 가 내려가는 방향이 보장된 대리 모델에서는 실행 시점 차단이 효과가 있다. 차단 없는 FCSRL 정책이 한도 12 를 넘는 seed 들(2개) 도 차단을 걸면 모두 한도 안으로 들어왔다 (theta 3.0 의 seed 별 비용은 결과 표 참고).
- 차단 신호를 예측기로 바꾸거나 비례 방식으로 바꾸는 이점은 없었다. BSM1 우기(e06) 와 같은 결과이며, 학습 구간(5 ~ 11월) 으로 맞춘 예측기가 겨울 검증 구간에서 이점을 잃었을 가능성이 있다. 현재 NH4 측정값만 쓰는 규칙이 가장 단순하고 충분했다.
- 차단을 건 정책(theta 3.0) 은 실제 운전 재생보다 공기를 7.6% 더 쓰고 하루 비용은 28.77 에서 6.62 로 낮다. 차단 없는 정책은 실제 운전보다 공기를 9% 덜 쓰고 비용 13.66 이다. 에너지와 수질 사이의 교환이며, 차단은 그 교환점을 수질 쪽으로 옮긴다.

### 한계

- 대리 모델의 예측 정확도가 낮다. 단조 제약 덕분에 방향은 물리적으로 맞지만 효과 크기는 이 모델에 달려 있다.
- 평가는 검증 구간이다. test 구간은 아직 쓰지 않았다.
- 차단 공기량 5,800 하나만 봤다. 학습 중에는 차단을 켜지 않았다.
