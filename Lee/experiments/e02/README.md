# Lee/e02: 같은 비교를 4배 긴 예산으로 다시 수행

## 목적

Lee/e01 과 같은 비교를 학습량만 4배로 늘려 다시 한다. e01 에서 라그랑주 승수가
10 갱신 내내 올라가는 중이었고(이진 비용 1.13~1.74, 상한 20 에 미달) 하루 비용이
한도 72 스텝에 못 미친 124~127 스텝에서 끝났다. 즉 e01 은 과도기에서 끝난 학습이라
"비용 정의를 바꾸면 제약을 만족할 수 있는가"와 "FCSRL 의 이점이 드러나는가"를
판정할 수 없었다.

e01 의 결과를 보고 예산을 바꾸는 것이므로 BRANCH_RULES 6절에 따라 새 실험 ID 로
기록한다. e01 의 한도, 가중치, 학습량, 결과는 바꾸지 않는다.

## 바꾼 것

| 항목 | Lee/e01 | Lee/e02 |
| --- | --- | --- |
| 갱신 | 10 | 40 |
| 전이 | 각 57,600 | 각 230,400 |

나머지는 모두 e01 과 같다. 비용 모드 2개(mean, binary), 방법 2개(PPO-Lag,
FCSRL + PPO), seed 3개(0, 1, 2), 한도(288, 72), PID 환산, 초기 상태, 관측 정규화
통계, 신경망 구조, 평가 방법, 코드가 같다. e01 과 같은 스크립트를 `--updates 40`
으로 실행하며 코드는 새로 쓰지 않는다. 준비 산출물(`e01_prepared`)도 같은 것을
그대로 쓴다.

## 가설 (사전 등록)

e01 과 같은 가설을 더 긴 예산에서 다시 본다.

- H1. 이진 비용에서 FCSRL + PPO 는 PPO-Lag 보다 순간 위반 시간이 짧다.
- H2. FCSRL 과 PPO 의 차이는 평균 비용 설정보다 이진 비용 설정에서 더 크다.
- H3. 이진 비용 설정은 평균 비용 설정보다 순간 위반 시간을 줄인다.
- H4 (e02 에서 추가). 40 갱신이면 이진 비용 실행이 하루 한도 72 스텝을 만족한다.
  e01 에서 만족한 seed 가 0/6 이었으므로, 과도기 때문이었는지 아니면 이 한도가 이
  보상과 환경에서 도달하기 어려운 수준인지 구분한다.

판정은 e01 과 같은 지표와 같은 방식(seed 3개 평균 ± 표준편차, 탐색적 Welch 검정,
다중 비교 보정 없음)으로 한다. 결과가 가설과 반대여도 그대로 기록한다.

## 실행

```bash
export BSM1_ARCHIVE=.../BSM1.zip
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
python -u Lee/experiments/e01/run_all.py --prepared <결과>/e01_prepared --out <결과>/e02_runs \
  --updates 40 --parallel 6 --upstream <원본 FCSRL 경로>
python -u Lee/experiments/e01/report.py --runs <결과>/e02_runs --prepared <결과>/e01_prepared \
  --out Lee/experiments/e02
```

준비와 학습 전 검사는 e01 에서 통과한 것을 그대로 쓴다
([e01 verification.json](../e01/verification.json)). run_all.py 가 실행할 때마다
준비 산출물의 sha256 과 원본 FCSRL 커밋의 무결성을 다시 검사한다.

실행 시간은 한 실행당 약 45~50분, 6개 병렬로 전체 약 1시간 40분을 예상한다
(e01 실측 속도 기준, 프로세스당 초당 약 88 전이).

## 미리 밝히는 한계

- 40 갱신도 수렴을 보장하지 않는다. 승수와 하루 비용의 추이를 함께 보고하고,
  여전히 과도기면 그렇게 적는다.
- 방법 간 초기 정책이 같지 않다(구조가 다르다). e01 과 같이 자기 초기 정책 대비
  변화량을 함께 본다.
- seed 3개의 탐색적 비교다. 유의하지 않다는 것이 동등성의 증명은 아니다.
- 결과를 본 뒤 한도, 가중치, 학습량을 바꾸지 않는다.
