## 감사 결과

FCSRL과 고정 표현 PPO 각각 seed0~9, 500회, 총20개 실행이다. 기존 e68의250회에서 학습량만 늘렸다. 한 실행당3,990,000전이와 무작위 초기1,520전이이며 전이 예산은 두 방법이 같다. 계산 시간은 같지 않다. 실행은 CPU에서 진행 중이며 GPU 사용으로 설정을 바꾸지 않았다.

16:43 기준 PPO seed0~4의5개가 정상 종료했다. 나머지는10개 실행 중,5개 대기다. 250회를 넘은 FCSRL0~4/PPO0~4의10개 실행은 모든 학습 로그 수치가 기존 e68과 정확히 같다(벽시계 시간 제외). 나머지 시작된5개도 기록된 접두부에서 불일치가 없고 아직 전체250회 재현으로 세지 않았다. manifest의 소스/준비물 해시는 모두 일치했다. 저장되지 않은 중간 가중치까지 검증한 것은 아니다.

학습 로그가 짧으면 통과하지 않는지, 비용 하나를 바꾸면 탐지하는지, 시간 차이는 제외하는지 작은 검산을 통과했다. 기존 report69.py는 zip 비교로 길이가 짧은 기록을 지나칠 수 있어 별도 감사에서 길이와 전체 수치 필드를 검사한다. 정상500회 결과에 대한 기존 판정을 바꾸는 수정은 아니다.

## 완료 뒤 해석 순서

1. 20개 종료와 해시,250회 접두부 재현을 확인한다. 모든 최종500회 결과를 보고하고 좋은 checkpoint나 seed만 고르지 않는다.
2. 기존 H1~H3 규칙은 그대로 보고한다. 별도로 한도.3 충족 수와 공기량, NH4 초과량, 위반일, DO를 함께 제시한다. 상대적으로 낫더라도 한도 미달이면 안전한 효율 개선이라고 하지 않는다.
3. 제약을 지키는 정책과 ABAC의 동일 날짜 전체 지표를 비교한다. 정상인 날짜만 선택한 공기량으로 우위를 주장하지 않는다.
4. 개선되면 그 예산에서 추가 학습이 도움이 됐다고 말한다. 실패하면 그 예산에서 해결되지 않았다고 말한다. 어느 경우도 무한 학습의 수렴 또는 불가능성을 입증하지 않는다.
5. FCSRL 핵심을 유지한다. 새 차단이나 네트워크를 자동으로 추가하지 않는다. 표현의 두 손실 기여를 분리하는 후속은 이 결과를 보고 정한다.

dev146일은 학습과 조정에 쓰였다. val40일은 반복 사용한 개발 자료다. holdout42일은 e68 정책 수집에서 제외했지만 과거 정책 및 대리 모델 학습에 쓰였고 test41일은 e66에서 평가했다. 이번 감사는 새 데이터 평가를 하지 않았다.
