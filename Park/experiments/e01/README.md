# Park/e01: FCSRL feasibility 점수로 실행 시점에 위험 행동을 막는 안전 차단

상태: **A0, A1 완료 (2026-11-09). 사전 등록한 H2 는 지지되지 않았다.** 결과를 본 뒤 규칙을 바꾸지 않았다. 바꾸는 시도는 새 실험 ID 로 한다.

## 목적

과제 4단계(기법 적용과 확장)에 해당한다. FCSRL 이 학습하는 feasibility 점수를 표현 학습의 보조 신호로만 쓰지 않고, 정책이 행동을 낼 때 직접 써서 순간 수질 위반을 줄일 수 있는지 확인한다.

## 배경

- FCSRL 은 feasibility 점수 `F(s) = E[max_t gamma^t c_t]` 를 예측하는 head 를 두고, 그 예측 손실로 encoder 를 학습한다. 정책과 Lagrangian 승수는 기존 PPO-Lag 그대로이고, 실행 시점에는 F 를 쓰지 않는다 (`Park/analysis/fcsrl_논문분석.md` 4.2절, 알고리즘 1).
- 논문 명제 4.1 에 따르면 비용이 0 또는 1 이면 `1 - F` 는 이후 위반이 일어나지 않을 확률에 해당한다. 이 전제는 Lee/e01 의 이진 비용 설정에서 성립한다. 이진 비용은 논문 전제를 되돌린 것이며 이 실험의 확장 요소가 아니다.
- Lee/e01 (이진 비용, 10 갱신) 의 FCSRL + PPO 는 건기 순간 위반 시간이 44.13 ± 10.99% 였고, 하루 72 스텝 한도를 만족한 seed 가 없었다 (0/3). 평균 제약만으로는 순간 위반이 많이 남는다.

## 바꾸는 것 한 가지

정책이 고른 행동을 환경에 넣기 직전에 다음 규칙을 적용한다.

```
F_hat = agent.feasibility(obs, action)     # F(s, a), 학습된 feasi_head 의 기댓값
if F_hat >= tau:
    action = 대체 행동                     # 최대 폭기 KLa5 = 240 (action = +1)
```

- F_hat 은 FCSRL 의 feasibility head 출력 분포의 기댓값이다. 원본 `train_encoder` 는 이 head 를 상태와 행동을 함께 넣은 표현 zsa(zs(s), a) 위에서 학습하므로, 정책이 고른 행동을 넣은 F(s, a) 를 쓴다. 코드는 `Park/code/shield.py`, `Park/code/agent.py` 의 `FCSRL.feasibility` 다.
- 대체 행동을 최대 폭기로 고른 이유는 상태가 필요 없는 가장 단순한 안전 행동이기 때문이다. DO PI 로 대체하는 방식은 적분 상태를 따로 관리해야 하므로 이번에는 쓰지 않는다.

### tau 의 의미 (feasibility discount 0.9 기준)

위반이 k 스텝 뒤에 확실히 일어나면 `F = 0.9^k` 다. 따라서 `tau` 는 대략 "몇 분 안에 위반이 예상되면 막을지" 를 정한다. F_hat 은 분포의 기댓값이므로 이 환산은 근사다.

| tau | k (스텝) | 대략의 시간 |
| --- | --- | --- |
| 0.7 | 3.4 | 17분 |
| 0.5 | 6.6 | 33분 |
| 0.3 | 11.4 | 57분 |

후보 tau 와 선택 방법은 아래 "사전 고정 조건" 에서 실행 전에 정한다.

## 단계

| A1 평가 시점 차단 | Lee/e01 과 같은 조건으로 학습한 FCSRL + PPO 마지막 정책에 차단을 붙여 평가한다 | 차단을 위해서는 없음 (기반 정책 학습은 필요) |
| B 학습 중 차단 (선택) | A1 이 의미 있을 때만, 학습 중에도 차단을 켜고 다시 학습한다 | 있음 |

A0 에서 F_hat 의 예측력이 단순 NH4 측정값보다 낫지 않으면, A1 은 진행하되 결론을 "F 의 추가 가치 미확인" 으로 적는다.

## 비교 조건

| 조건 | 설명 |
| --- | --- |
| 차단 없음 | Lee/e01 이진 비용 FCSRL + PPO 그대로 |
| F 차단 | 이 실험의 확장. F_hat >= tau 이면 최대 폭기 |
| 규칙 차단 (대조) | 현재 NH4 측정값 >= theta 이면 최대 폭기. theta 는 F 차단과 개입 비율이 같아지도록 학습 날짜에서 정한다 |
| 무작위 차단 (대조) | 같은 개입 비율로 무작위 스텝에 최대 폭기 |

규칙 차단과 무작위 차단은 "아무 때나 공기를 더 넣어도 위반은 준다" 는 효과를 F 의 효과와 구분하기 위한 대조군이다.

## 가설 (사전 등록)

- H1. F 차단은 차단 없음보다 순간 위반 시간을 줄이고 에너지를 늘린다. 공기를 더 넣으면 거의 당연히 생기는 결과이므로 이것만으로 성과로 세지 않는다.
- H2 (주 가설). 개입 비율이 같을 때 F 차단은 규칙 차단과 무작위 차단보다 순간 위반 시간을 더 줄인다.
- H3. A0 에서 F_hat 의 위반 예측 AUROC 가 현재 NH4 측정값보다 높다.

가설이 기각되는 결과도 그대로 기록한다.

| 항목 | 값 |

| 정책 | 직접 작성한 코드로 Lee/e01 과 같은 설정을 학습한 마지막 정책, seed 0, 1, 2 |

| tau 후보 | 0.3, 0.5, 0.7 |
| tau 선택 | seed 마다 학습 날짜(건기 0 ~ 6일, 각 날 시작 상태에서 하루씩 7번) 에서 차단을 켜고 돌린다. 하루 평균 위반 스텝이 한도 72 이하인 후보 중 가장 큰 tau (개입이 가장 적은 것) 를 고른다. 모두 72 를 넘으면 0.3 을 쓴다. 평가 구간 결과로 고르지 않는다 |
| 대조군 맞춤 | 무작위 차단의 p 는 고른 tau 의 학습 날짜 개입 비율이다. 규칙 차단의 theta 는 차단 없는 학습 날짜 운전에서 NH4 측정값이 theta 이상인 스텝 비율이 그 개입 비율과 같아지는 분위수다. 무작위 차단 난수 seed 는 정책 seed 와 같다 |
| A0 지표 | 차단 없는 학습 날짜 운전에서 각 스텝 t 의 정답을 "t ~ t+6 (35분) 안에 위반 스텝이 있는가" 로 두고, F(s_t, a_t) 와 NH4 측정값의 AUROC 를 잰다. 하루 끝 6 스텝은 정답을 다 볼 수 없어 뺀다 |
| H2 판정 | 건기 평가에서 F 차단의 순간 위반 % 가 규칙 차단과 무작위 차단보다 모두 낮은 seed 가 3개 중 2개 이상이고, seed 평균도 둘보다 낮으면 지지로 적는다. 개입 비율이 실제로 다르게 나오면 그 차이를 함께 적는다 |
| 평가 | Lee/e01 과 같다. 14일 연속 운전, 후반 7일 집계, 건기와 우기 (우기는 분포 밖 점검) |
| 학습 중 차단 (B) | A1 결과를 보고 진행 여부를 정한다 |

위 규칙은 2026-11-09 본 학습 전에 고정했다. 그 전에 코드 연결 시험(1 갱신 정책 하나, 건기 평가)에서 차단기 3종의 수치를 한 번 보았다. 그 시험은 개입 비율이 서로 달라 비교 근거가 아니며, 위 규칙은 평가 결과를 쓰지 않는다.

## 측정 지표

- Lee/e01 과 같은 지표: 폭기 에너지 kWh/day, 유량 가중 평균 NH4, 순간 위반 시간(스텝 비율과 하루 위반 스텝), CVaR, 한도 72 만족 여부
- 추가: 개입 비율(차단이 걸린 스텝 비율), 위반 1 스텝을 줄이는 데 든 추가 에너지

## 미리 밝히는 한계

- 최대 폭기만 써도 건기 순간 위반 시간이 15.82% 다 (Lee/e01 기준 제어). 차단으로 그보다 낮출 수는 없다.
- F_hat 은 차단 없이 학습한 정책의 궤적으로 학습됐다. 차단이 행동을 바꾸면 상태 분포가 달라져 F_hat 이 덜 정확해질 수 있다.
- feasibility discount 0.9 는 약 10 스텝(50분) 앞만 본다. 명제 4.1 의 확률 해석은 gamma 가 1 에 가까울 때의 이야기이므로, 이 실험의 F_hat 은 "가까운 미래의 위험 점수" 로만 해석한다.
- Lee/e01 의 정책은 10 갱신만 학습했다. 수렴한 정책이 아니다.
- 차단은 위반이 없다는 보장을 주지 않는다. F_hat 이 틀리면 막지 못한다.
- BSM1 은 물리 시뮬레이터이고 실제 공정이 아니다.

## 실행 환경

macOS, CPU, Python 3.13.5, torch 2.15.0, numpy 2.5.4, scipy 1.18.1, numba 0.68.1, bsm2-python 0.0.16, 원본 FCSRL d882b91. 설치는 `Park/code/README.md`. 환경 검사 기준값 12개 통과 (`check_env.json`).

## 실행 명령

```bash
cd Park/code
export BSM1_ARCHIVE=<BSM1.zip> WANDB_MODE=disabled OMP_NUM_THREADS=1
python prepare.py --out <결과>/prepared
python check_env.py --prepared <결과>/prepared --out ../experiments/e01/check_env.json
for s in 0 1 2; do python train.py --method fcsrl --seed $s --updates 10 --prepared <결과>/prepared --out <결과>/runs/fcsrl_s$s; done
cd ../experiments/e01
for s in 0 1 2; do python run_e01.py seed --seed $s --prepared <결과>/prepared --runs <결과>/runs --out <결과>/e01; done
python run_e01.py report --out <결과>/e01 --md results.md
```

실행 코드는 이 기록과 함께 커밋한 `Park/code/` 와 `run_e01.py` 다 (실행은 커밋 직전 작업 트리에서 했고, 이후 바꾼 것은 문서뿐이다). 상태 파일, 체크포인트, seed 별 JSON 은 저장소 밖에 있다.

## 실행 결과

전체 표는 [results.md](results.md). 요약 (건기, seed 3개 평균 ± 표준편차):

| 조건 | 폭기 kWh/day | 순간 위반 % | 개입 % |
| --- | --- | --- | --- |
| 차단 없음 | 3606 ± 76 | 42.99 ± 8.11 | 0 |
| F 차단 (tau 0.3) | 3802 ± 42 | 25.17 ± 3.28 | 27.1 ± 7.0 |
| 규칙 차단 | 3747 ± 62 | 29.08 ± 5.78 | 19.4 ± 2.3 |
| 무작위 차단 | 3931 ± 32 | 20.35 ± 0.85 | 45.7 ± 1.8 |

기반 정책의 차단 없음 결과(42.99 ± 8.11%)는 Lee/e01 이진 비용 FCSRL + PPO (44.13 ± 10.99%) 와 비슷하다.

### 사전 등록 가설 판정

- H1 지지. F 차단은 순간 위반을 17.8%p 줄이고 폭기 에너지를 196 kWh/day 늘렸다. 공기를 더 넣은 결과이므로 성과로 세지 않는다.
- H2 지지 안 됨. F 차단이 두 대조군보다 위반이 낮은 seed 는 0/3 이다. 다만 이 비교는 공정하지 않게 끝났다. 학습 날짜에서 맞춘 개입 비율(약 44 ~ 47%)이 평가 구간에서는 F 27%, 규칙 19%, 무작위 46% 로 달라졌다. 무작위 차단은 상태와 무관하게 정한 비율대로 개입하지만, 상태에 따라 개입하는 두 차단은 평가 구간에서 덜 개입했다.
- H3 형식상 지지, 의미는 작다. AUROC 가 세 seed 모두 F(s, a) 0.998 ~ 1.000, NH4 측정값 0.992 ~ 0.996 이다. 위반이 길게 이어지는 구간으로 나타나 양성 비율이 51 ~ 59% 이고, 현재 NH4 만으로도 35분 안의 위반을 거의 완벽히 맞힌다. F 가 더할 정보가 거의 없는 과제였다.
- tau 규칙: 세 seed 모두 어떤 후보도 학습 날짜에서 한도 72 를 만족하지 못해 규칙대로 0.3 을 썼다. tau 0.7 과 0.3 의 차이가 작았다 (하루 위반 스텝 약 1 차이).

### 사후 분석 (사전 등록 아님, 근거로 쓰지 않는다)

개입 비율이 달라 직접 비교가 안 되므로, 늘어난 에너지 1 kWh/day 당 줄어든 순간 위반 %p 를 seed 평균으로 계산했다. F 차단 0.091, 규칙 차단 0.099, 무작위 차단 0.070 이다. F 차단은 무작위보다 효율적이었지만 단순 NH4 규칙보다 낫지 않았다. seed 3개, 평균값 기준이라 우열로 해석하지 않는다.

### 해석과 한계

- 이번 조건에서 F 는 "지금 NH4 가 높은가" 와 거의 같은 신호로 동작했다. feasibility discount 0.9 는 약 50분 앞만 보고, 위반이 이미 시작된 뒤에 점수가 올라간다. 최대 폭기를 넣어도 NH4 가 내려가는 데 시간이 걸리므로 늦게 거는 차단은 효과가 제한된다.
- 개입 비율을 학습 날짜에서 맞추는 방식은 평가 구간에서 유지되지 않았다. 한 점을 맞추는 대신 여러 tau, theta, p 로 곡선(에너지 대 위반)을 그려 비교해야 한다.
- 정책은 10 갱신만 학습했다. 차단은 평가 시점에만 켰다 (단계 B 미실행).
