# e74: 순간 NH4 초과를 넣은 비용으로 다시 학습

**2026-11-21 완료. dev 한도 4.75 충족은 FCSRL, 고정 표현 PPO 모두 10/10 (H2 충족). FCSRL 대 고정 표현 PPO 는 차이 불명확 (H1 2/10). 새 ABAC 대비 FCSRL 은 평균 네 지표 모두 낮지만 공기 차이는 0.7 % 이고 네 지표 모두 나은 seed 는 5/10 이다. val 에서는 어떤 방법도 4.75 를 지키지 못한다.** [결과 표](results.md), [요약](summary.json), [사전 조건](protocol.json), [환경](env74.py), [학습](train74.py), [비교군](baselines74.py), [실행](run74.py), [집계](report74.py). holdout 과 test 는 쓰지 않았다.

## 결과 요약

dev 146일 x 5, 표본 행동 (고정 seed 3개 평균), seed 0 ~ 9, 갱신 500번. 20개 학습과 평가가 오류 없이 끝났다 (2026-11-21 11:44 ~ 14:13). 대리 환경 결과이며 현장 성능이 아니다.

- **H2 (주): 두 방법 모두 dev 한도 10/10 충족.** 승수는 마지막 100번 동안 한 번도 상한 100 에 닿지 않았고, 마지막 50번 학습 비용은 seed 별 2.3 ~ 3.6 으로 학습 한도 3.17 근처에 모였다. e68 ~ e72 의 누적 예산 비용에서와 달리 이 비용은 스텝마다 신호가 있어 승수가 제 역할을 했다.
- **H1: 차이 불명확 (FCSRL 우위 짝 2/10, 고정 표현 PPO 우위 짝 0/10).** FCSRL 은 공기가 10/10 짝에서 낮고 평균 5.8 % 적지만, 비용 스텝이 낮은 짝은 3/10, NH4 초과가 낮은 짝은 5/10 이다. 공기와 제약의 교환이며 동시 개선이 아니다. 일곱 번째 비교에서도 FCSRL 고유 효과는 사전 기준에 못 미친다.
- **H3 (새 ABAC 대비):** FCSRL 평균은 공기 47,497 대 47,853 (0.7 % 적음), 비용 스텝 3.33 대 4.18, 위반율 3.02 대 5.07, NH4 초과 1.50 대 1.98 로 네 지표가 모두 낮다. 그러나 seed 별로 네 지표가 모두 나은 것은 5/10 이고, 공기가 낮은 seed 는 7/10 (seed 0 은 60,659 로 많다) 이다. 고정 표현 PPO 는 공기가 5 % 많아 우위가 아니다 (5/10). 따라서 "같은 공기에서 제약을 더 잘 지킨다" 는 평균 수준의 관찰이며, 공기 절감 주장은 할 수 없다.
- **e68 ABAC (설정값 2.9) 대비:** 두 방법 모두 공기는 19 ~ 24 % 적지만 비용 스텝과 위반율이 높아 우위가 아니다 (0/10, 1/10). 같은 공기 대비 제약의 교환이다.
- **이전 비용 (예산 초과 0.3) 기준으로는** FCSRL 2/10, 고정 표현 PPO 5/10 만 지킨다. 새 비용은 순간 NH4 를 줄였지만 하루 누적 예산 쪽 여유는 e72 (0.24, 0.23) 보다 조금 줄었다.
- **val 은 모든 방법이 한도 밖이다.** FCSRL 8.86, 고정 표현 PPO 7.10, 새 ABAC 8.49, e68 ABAC 6.04, 기록 운전 30.04. 기록 운전 재생도 val 에서 30.04 로 dev (4.75) 의 6 배라, dev 에서 정한 한도 4.75 가 val 조건에는 맞지 않는다 (원인은 분리하지 않았다). val 에서도 H1 은 차이 불명확 (1/10 대 1/10) 이고 비용은 고정 표현 PPO 가 낮다.
- 첫 수집 검사: 고정 표현 PPO 10/10 이 e72 와 같다. FCSRL 은 가능성 목표가 새 비용으로 바뀌어 0/10 이 다르며, 이는 사전 조건에서 허용한 차이다.

## 다음 (사전 조건)

사전 조건상 H2 FCSRL 이 8/10 이상이므로 같은 설정으로 새 seed 10 ~ 19 확인 뒤 holdout 한 번을 제안한다. 다만 H1 은 차이 불명확이라 확인할 수 있는 주장은 "이 비용과 학습 방식에서 RL 정책이 dev 한도를 지키고 새 ABAC 와 비슷한 공기에서 비용과 위반을 줄인다" 이며, FCSRL 고유 효과는 아니다. val 에서 모두 한도 밖이라 holdout 에서도 한도 충족을 기대하기 어렵다. 진행 여부는 사용자가 정한다.

## 왜 하는가

[e73](../e73/README.md) 에서 정책 + 예산 속도 차단은 하루 예산 한도 (예산 초과 스텝 0.3) 를 9/10 seed 에서 지키고 ABAC 보다 공기를 약 30 % 적게 썼다. 그러나 NH4 > 4 인 스텝이 하루 약 27개 (기록 운전 재생 4.75, ABAC 2.38) 였고 순간 NH4 초과량은 ABAC 의 14 배였다. e68 비용은 하루 평균만 보므로 NH4 를 4 근처에서 오르내리게 해도 비용이 없다.

사용자 결정 (2026-11-21): 순간 초과를 비용에 넣고 다시 학습한다.

## 바꾼 것

- **비용:** 스텝마다 1[NH4 > 4 또는 그날 누적합이 380 을 넘은 뒤]. 원 FCSRL 처럼 이진 비용이라 가능성 학습과 맞는다.
- **한도:** dev 기록 운전 재생 수준, 하루 4.75 스텝 (확인 값 4.747). e68 이 한도 0.3 을 정한 방식과 같다. e68 ABAC (설정값 2.9) 는 2.51 이다.
- **비교군:** e68 비교군 코드와 격자로 새 한도에 맞춰 다시 고른다 (한도를 지키는 조합 중 공기 최소).

## 바꾸지 않는 것

e72 의 학습 방식을 비율째 옮기고 새로 조정하지 않는다. PID 이득 x 25 / 평가 한도, 적분 상한 묶음, 승수 상한 100, 학습 한도 = 평가 한도 x 2/3 (3.17), 갱신 500번, 관측 (남은 예산 포함), 보상, 행동, dev 146일 학습, 표본 행동 평가. 두 방법에 똑같이 적용한다.
