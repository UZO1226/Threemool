# Park/e53: NH4 분석계 지연 보정 (Kaggle DARROW)

상태: **사전 등록 (2026-11-20).** 가설과 판정 규칙은 검증 결과를 보기 전에 정했다. 고를 설정은 없다. 대표는 바꾸지 않는다.

## 목적

팀 중간점검 (Yoo/analysis/TEAM_RESEARCH_REVIEW_20261117.md) 8절 6번은 "센서, 입력 지연" 에서의 견고성을 요구했다. Park/e46 은 NH4 분석계가 15분 늦으면 대표가 공식 기준선보다 여전히 낫지만 (5.762), 30분 늦으면 9.62 로 기준선 (10.79) 에 가까워진다고 보고하고 "그 이상은 지연을 아는 예측이 필요하다" 고 적었다. 이 실험은 그 보정을 만들어 시험한다.

## 방법

- 보정 (`Park/code/delay_comp.py`, Smith 예측기 방식): 분석계가 d 스텝 늦은 NH4 를 줄 때, 늦은 값에서 출발해 그 뒤 d 스텝 동안 실제로 넣은 구간 공기량, 지연 없는 다른 센서 값 (NO3, DO 3개), 그 시각의 외부 입력으로 대리 모델 (환경이 쓰는 구성원을 뺀 4개 평균, 대표 차단과 같음) 을 굴려 지금 NH4 를 추정한다. 정책과 차단은 추정한 NH4 를 본다. 새 정보는 쓰지 않는다 (대표 차단이 이미 쓰는 정보)
- 지연과 평가 방식은 Park/e46 과 같다 (`rollout_log(delay=d)`). 대표 (FCSRL 4 x 16 + 대표 차단, 묶음 5개) 를 30분 (d = 2), 15분 (d = 1) 지연에서 보정을 붙여 평가한다. 참고로 ABAC (Park/e43 고름) 에도 같은 보정을 붙인다
- 보정 없는 값은 Park/e46, 지연 없는 값은 Park/e35, e43 을 쓴다
- 사전 점검 (학습 구간 4일, ABAC, 판정에 쓰지 않음): 보정은 NH4 추정 RMSE 를 15분 지연에서 0.096 에서 0.039 로, 30분 지연에서 0.180 에서 0.067 로 줄였다

## 평가

검증 40일 x 구성원 5개 = 200 에피소드, 결정적. test 는 쓰지 않는다.

## 가설 (사전 등록)

- H1. 30분 지연에서 보정한 대표의 하루 비용이 보정 없는 대표 (Park/e46) 보다 낮은 묶음이 5개 중 4개 이상이고 평균도 낮다
- H2. 30분 지연에서 보정한 대표가 묶음 5개 모두 공식 기준선 (기본 PPO-Lag, 90,121, 10.79) 보다 공기량과 비용이 둘 다 낮다

참고 (판정 없음): 15분 지연의 같은 비교, 보정한 ABAC, 30분 보정과 지연 없음의 차이.

## RESULT.md 처리 (미리 정함)

대표 방법은 바꾸지 않는다 (지연은 운전 조건이고, 보정은 지연이 있을 때 붙이는 부품으로 적는다).

- H1, H2 지지: "대표 차단과 같은 정보로 만든 지연 보정을 붙이면 NH4 분석계 30분 지연에서도 대표가 공식 기준선보다 둘 다 낮다" 고 적는다
- H1 지지, H2 기각: "보정이 30분 지연의 비용을 낮추지만 기준선보다 둘 다 낮지는 않다" 고 적는다
- H1 기각: "대리 모델로 굴린 지연 보정은 30분 지연에 도움이 되지 않는다" 고 한계에 적는다

## 미리 밝히는 한계

- 보정은 대표 차단과 같은 대리 모델 계열을 쓰고 환경도 같은 계열이라, 보정이 유리한 쪽이다 (Park/e38 처럼 모델이 틀리면 보정도 틀린다)
- 지연은 일정한 순수 지연만 본다. 분석계의 잡음, 결측, 변하는 지연은 보지 않는다
- 검증 구간은 e10 부터 반복해서 썼다
